# M2.1 场景通信扩展

沿用 M1.5 的本地 origin、CSP、WebView2 请求编号与协议 version=1。应用独立启动仍使用 `apps.launch {appId}`，没有改变其重复行为。

| 消息 | 参数 | 允许界面 / 结果 |
| --- | --- | --- |
| `scenes.save` | `{scene}`，完整 Scene 及动作、显式依赖 | Workspace；事务保存后返回 settings |
| `scenes.remove` | `{sceneId}` | Workspace；只删除场景与固定引用，返回 settings |
| `scenes.reorder` | `{sceneIds}`，完整排列 | Workspace；返回 settings |
| `scenes.pickTarget` | `{kind}`，application/file/folder/script/workingDirectory/waitTarget | Workspace；原生选择器返回 cancelled 或 target，不执行目标 |
| `scenes.run` | `{sceneId}` | 三个界面；立即返回 execution 与 executions，后台继续调度 |
| `apps.remove` | `{appId, confirmReferences?}` | Workspace；有场景引用时，必须明确传 true |

`app.getState` / `state.changed` 补充 `settings.scenes` 和 `executions`。新增宿主事件 `scene.executions {executions}` 传递执行快照；三个 WebView 不运行自己的模拟调度器。新创建的界面通过握手获取当前状态。

SceneAction 的应用引用字段为 `appEntryId`，已有应用引用不保存 target/arguments/workingDirectory 副本。高级直接路径模式使用 `appEntryId=null`。脚本只接受 `argumentList`，每个元素是一条独立参数；不接受脚本原始命令字段。普通程序参数仍由原有 NativeLaunchService 校验。

配置校验在核心完成：稳定 GUID、合法类型、HTTP/HTTPS、本地绝对路径、合法脚本扩展、延迟及超时上限、依赖完整性、无环。普通文件不能借可执行扩展绕过应用/脚本动作。场景保存请求允许最多 1 MiB，配置存储沿用 16 MiB 总容量保护；都不按场景数量设置低上限。

每个动作报告 Pending / Running / Success / Skipped / Failed；执行汇总 Pending / Running / Success / PartialSuccess / Failed。code 区分 submitted、process_appeared、window_appeared、already_running、wait_*_timeout、script_completed、script_exit_error、script_timeout、previous_script_running、reference_invalid 与 dependency_failed。目标路径不可读等补充信息写入 diagnostic。

`Success` 的含义由动作完成条件决定。submitted 只代表 Windows 接受启动/打开请求；process_appeared 不代表应用加载完毕；window_appeared 只代表匹配的可见窗口已出现。脚本默认需要退出码 0 才算成功。

运行中删除或编辑场景不会修改已创建实例的场景快照。每个应用动作在启动时读取最新应用库配置；删除应用可能让尚未启动的引用动作失败，并按依赖规则传播。取消固定不删除任何业务记录。
