# Desktop Hub — M2.3 Windows 桌面系统集成与常驻体验完善

> **阶段定位：** 在 M1 / M1.5 / M2.1 / M2.2 的既有成果上完成 Windows 桌面级系统集成，让 Desktop Hub 可以安全、稳定地长期常驻使用。
>
> **正式依据：** 项目根目录 `PRD.md`（v0.7.1）、已验收的 UI 原型、现有实施报告和当前真实代码。
>
> **本轮重点：** 桌面图标整体隐藏与恢复、托盘与生命周期、当前用户开机自启、Mini/Dock/Workspace 窗口行为、独立快捷键、前台全屏游戏保护、系统主题跟随、配置及异常恢复。
>
> **禁止越界：** 不重构现有应用库/场景引擎/文件索引，不强行嵌入壁纸或替换 Explorer，不提前做正式安装包及跨平台适配。

## 0. 开工前的强制检查

你作为 Desktop Hub 的 Windows 客户端工程师，先完成下列核实，然后直接执行开发，而非停留在建议层面：

1. 阅读 `PRD.md`，特别关注 SYS-03、UI-01～UI-07、FM-14、DM-14/15、NFR-01～04 与 M2 验收要求。不要将 UI 示例中的模拟行为当成已经完成的真实能力。
2. 检查已完成项目及 `docs/M1_Implementation_Report.md`、`docs/M1.5_Implementation_Report.md`、`docs/M2.1_Implementation_Report.md`、`docs/M2.2_Implementation_Report.md`（存在则读取）。**核实 M2.2 是否真正通过验收；如有阻塞性遗留问题，应先报告并在本轮范围内最小修复。**
3. 核实实际技术栈、原生宿主/WebView 通信、配置持久化和窗口控制代码。复用已有的功能，不重复建造第二套托盘、窗口管理或配置服务。
4. 检查 Git 状态，保护所有用户已有未提交改动；在可行时建立本轮开始前的可回退节点，提交必须只包含本阶段修改。
5. 编写简短分步实施计划（子模块、风险、测试安排），随后继续编码、构建和验证。**禁止重画/重写已经认可的 Quiet Desktop UI。**

## A. 桌面图标整体隐藏与恢复（最高安全优先级）

### A1. 功能边界

- 仅管理 **Windows 桌面图标整体可见性**，不得删除、移动、重命名、隐藏文件属性、修改文件内容或迁移用户桌面文件。
- 不支持“逐个文件图标隐藏”；不得通过搬移文件或创建替代桌面目录来模拟隐藏。
- 在设置中提供明确的「隐藏桌面图标 / 显示桌面图标」操作及当前状态提示。
- 首次启用隐藏前，必须展示它不会删除文件的说明，并要求用户选择完整退出时的策略：**退出后恢复图标** 或 **退出后保持隐藏**；没有选择不允许执行首次隐藏。
- 记录隐藏前的已知图标可见性状态、用户设置、最近一次成功变更结果以及操作是否需要恢复；不要假定首次启动时图标一定可见。
- **命令是设置目标状态（显示/隐藏），而不是没有状态检测的盲目 Toggle**。重复点击“隐藏”不能导致图标反而显示。

### A2. 实现与异常保护

- 优先评估 Windows Shell 公开、可解释的方式；如只能依赖未公开接口、Shell 窗口遍历或脆弱的 Explorer 实现，请记录兼容性证据、失败模式和回退方案。**不能为兑现功能要求而使用易损、不可恢复的硬编码窗口链或任意重启 Explorer。**
- 原生接口执行结果必须真实反馈给前端。无法可靠读取或设置状态时应明确显示「当前状态未知/操作不受支持」，不得假装成功。
- Explorer 重启、Windows 注销重新登录、应用意外退出后，尽可能重新核对图标状态；仅在有明确状态依据且符合用户授权策略时进行恢复。
- 恢复能力不能完全依赖 Desktop Hub 正常运行。必须在首次隐藏前提供并在设置中长期展示 **Windows 原生恢复路径：桌面空白处右键 → 查看 → 显示桌面图标**（菜单文字随系统语言变化）。
- 启动恢复逻辑不得无声覆盖用户在软件外主动进行的图标显示设置；遇到外部修改应提示冲突或遵守明确记录的用户策略。
- 需要区分正常退出、关闭 Workspace、最小化到托盘、Windows 关机/注销以及崩溃后重新启动，不要将它们统一视作“退出”。
- 无法保证所有系统场景中的自动恢复成功时应如实在验收报告注明。

### A3. 手工测试

在可回退测试环境中完成：初始显示、初始隐藏、连续点击、用户取消首次授权、正常退出恢复、退出保持隐藏、Explorer 重新启动、Desktop Hub 强制退出后重新启动、在应用外更改显示状态。**切勿在用户真实桌面上进行删除/迁移测试**。

## B. 系统托盘与程序生命周期

- 使用现有应用生命周期服务；如尚未实现则提供单一托盘图标，具备：**打开 Workspace、显示/隐藏 Mini、打开设置、显示/恢复桌面图标、完整退出**，避免重复托盘图标。
- 关闭 Workspace 只关闭/隐藏该工作空间，不应终止托盘后台实例。用户点击“完整退出”才关闭整体应用并释放资源。
- Mini/Dock/Workspace 隐藏后遵守已选交互模式，不在后台继续不必要的动画刷新或高频轮询。
- 单实例保护；再次启动程序时应将请求转发给已运行实例或安全唤出 Workspace，而非另起一套文件监测/托盘服务。
- 明确完整退出时的清理顺序：停止新的唤出/调度请求 → 按用户配置处理桌面图标 → 解除全局快捷键 → 释放托盘、窗口、监听和其他资源 → 正常退出。
- 已经运行的独立用户应用不应因 Desktop Hub 退出而被强制终止；对已经由用户触发的场景执行，按现有引擎能力清晰处理退出中的操作，不得误杀用户软件。
- 支持 Windows 资源管理器重启后的托盘重建/恢复（在技术方案允许范围内验证）。

## C. 当前用户开机自启

- 设置中提供开机自启开关，**首次安装和首次启动均默认关闭，只有用户主动开启才注册**。
- 仅为**当前 Windows 用户**注册；不得默认写 HKLM、创建全体用户的启动项、设置管理员任务或申请提权。
- 使用官方支持的当前用户启动机制，并在报告中注明采用的途径，例如 HKCU Run 或当前用户 Startup 快捷方式；不能使用 RunOnce 模拟永久自启。
- 开启后可查询真实系统注册状态；关闭时仅移除 Desktop Hub 自己创建的条目，不改动其他程序的启动项。
- 支持路径带空格，正确处理可执行文件路径与命令行参数。便携版移动位置造成的失效启动项应提供可恢复提示，不能无限重复自启错误。
- 登录自启时以安静常驻为主，不自动弹出全屏 Workspace，不自动运行用户“创作”“游戏”等场景，也不自动隐藏桌面图标，除非已有明确且单独的授权策略。
- 应用设置与真实系统状态不一致时显示提示并允许修复；不能只更新 UI 开关就报告成功。

## D. Mini / Dock / Workspace 原生窗口行为

保持原有三个界面和 UI，不重新设计。完成或修复：

- **Mini：** 半透明细长工具栏；显示 2–4 个用户选择的应用/场景混合入口，单击后沿用已存在的真实启动服务；保留位置、尺寸、透明度；不永久遮挡普通软件。
- **Dock：** 边缘停留约 500ms 触发；普通程序前台允许唤出；全屏游戏与屏蔽名单程序前台禁止；可调整位置、大小与紧凑/标准图标密度；完整保留“常用应用 / 快捷场景”两区和执行状态。
- **Workspace：** 类 Launchpad 全屏或近全屏；由独立快捷键或 Mini/Dock 打开，可在普通应用上方临时展示；`Esc` 关闭后尽可能返回先前仍有效的前台窗口；不试图激活已经退出或句柄失效的窗口。
- 同一时间避免重叠 Mini/Dock/Workspace 造成重复输入、鼠标穿透错误和焦点抢夺；应在符合用户配置的情况下处理面板之间的优先级。
- 窗口位置、尺寸使用 Windows DPI 感知的逻辑单位，单显示器为首版主目标；系统缩放变化、分辨率变化后必须保证关键窗口仍在可见工作区内。
- 不得依赖替换 Explorer、将 WebView 嵌入未公开 WorkerW 层、持续置顶覆盖全屏游戏等脆弱技巧。真正壁纸嵌入不是本轮验收标准。

## E. 全局快捷键与全屏/程序屏蔽

- Dock 和 Workspace 提供**两套独立快捷键**，均可编辑、保存，并在下次启动后生效。
- 使用系统可管理的注册/注销机制；注册失败、冲突、不可用的组合键必须明确提示，保留之前有效的快捷键，不能悄悄覆盖系统快捷键。
- 在窗口销毁、热键更改、进程退出时正确注销；防止重复注册与多实例冲突。
- 对独占全屏及无边框全屏游戏尽力识别，结合用户自定义的**前台程序屏蔽名单**；不得把 Desktop Hub 的 Workspace 自己误判为游戏。
- 屏蔽名单与前台判断用于控制 **Mini/Dock/Workspace 的自动唤出**，而不是杀掉目标程序、注入钩子或改变全屏应用设置。
- 游戏识别并非 100% 可靠。对于识别不明确的程序，提供用户可见的排除名单作为可靠覆盖手段；在测试记录中列明误判/漏判边界。
- 尤其验证：普通浏览器前台可快捷键唤出；屏蔽程序前台不能唤出；应用自身 Workspace 近全屏时可以正常关闭；Esc 返回仍有效的原窗口。

## F. 外观与低资源常驻

- 自动跟随 Windows 深色/浅色主题，主题发生变化时正确刷新 UI；当前 UI 若已有此能力只需修补，不另造主题框架。
- 保留 Quiet Desktop：极简纯色、适度毛玻璃、现代几何、低干扰动画，允许关闭高成本透明效果。
- 页面/窗口收起后暂停无需运行的动画和重复渲染；不得为了悬停检测进行高频全屏截图或忙等待。
- 文件监测属于 M2.2 功能，继续按既有授权目录后台工作，避免本轮窗口改动导致监听器重复创建。
- 长期资源消耗需要实测并记录：登录自启后空闲、Mini 显示、Dock 展开、Workspace 展开、M2.2 文件变化时的 CPU/内存观察。若无法可靠测量，不得杜撰指标。

## G. 设置、持久化与原生通信

在现有配置结构上新增/完善，不创建第二套互相冲突的设置源：

- 退出时桌面图标策略（首次隐藏用户明确选择）。
- 已知桌面图标状态及安全恢复所需元数据。
- 当前用户开机自启真实状态与设置值。
- Mini/Dock 位置、尺寸、密度、触发行为。
- Dock / Workspace 独立快捷键。
- 全屏屏蔽程序名单。
- Windows 主题跟随和动画偏好。

要求配置原子/安全写入或现有等价机制，旧版用户应用库、场景、资源索引、标签、收藏完全兼容。WebView2/原生消息边界沿用已存在的验证规则，只允许明确列出的系统操作；禁止允许前端发送任意 PowerShell/CMD 字符串来管理 Windows 设置。

## H. 严格不做事项

- 不实现文件物理迁移、文件删除、桌面文件重命名、单文件图标隐藏。
- 不提前开发新的场景引擎、应用库或文件标签系统；只修复系统集成引发的兼容性问题。
- 不实现任意 Windows Shell 替换、真实壁纸强绑定或游戏窗口注入。
- 不默认启用开机自启；不默认隐藏桌面图标；不在 Windows 登录时自动执行用户场景。
- 不开发安装包、自动更新、云同步、遥测、跨电脑配置迁移或多显示器完整适配（留到 V1/未来阶段）。
- 不无故重新设计 Mini/Dock/Workspace，不大规模重构已经稳定的 UI 和业务代码。

## I. 实际测试与验收清单

必须实测，并标记“真实通过 / 自动化通过 / 需人工验证 / 未实现或失败”，至少包括：

1. 首次点击隐藏桌面图标时出现解释和退出策略选择，取消后不改变系统状态。
2. 选择“退出恢复”后，成功隐藏、完整退出、图标恢复；重复调用隐藏不会切换回显示。
3. 选择“退出保持隐藏”后，完整退出状态符合选择，并提供原生恢复说明。
4. 程序异常终止、重启以及 Explorer 重启后进行状态核对和可恢复性验证，说明无法保证的行为。
5. 手动通过 Windows “查看 → 显示桌面图标”能在 Desktop Hub 不运行时恢复图标。
6. 托盘可打开 Workspace、显示 Mini、进入设置及完整退出，不产生多个托盘图标。
7. Workspace 关闭不退出整个应用；完整退出释放资源但不终止用户已启动的软件。
8. 两次启动程序不会出现两个独立后台索引器、托盘实例或重复热键注册。
9. 开启当前用户开机自启后系统注册项可查，关闭后能干净移除且不误删其他程序项；登录启动不自动弹全屏 Workspace。
10. 快捷键修改生效，冲突明确提示，退出释放，全屏屏蔽不被绕过。
11. 普通应用前台唤出 Workspace，Esc 返回原应用；原应用关闭时安全回退。
12. Dock 在允许情况下约 500ms 悬停展开，受屏蔽应用和全屏游戏前台时不展开。
13. Mini 的混合应用/场景入口、Dock 两区、Workspace 完整应用启动台在系统集成后仍能启动真实目标。
14. 主题自动跟随 Windows，关闭动画后无多余视觉刷新；Mini/Dock/Workspace 布局在不同 Windows 缩放下不跑出屏幕。
15. 重启 Desktop Hub 后，开机自启设置、窗口配置、屏蔽名单和快捷键仍可读取。
16. M1.5 多应用启动与固定入口功能无回归。
17. M2.1 场景创建、执行调度、重复跳过、等待及错误反馈无回归。
18. M2.2 文件索引、目录监测、标签、收藏、失效修复及清理功能无回归。
19. 全部相关本地功能断网仍可工作，未新增强制联网依赖。
20. Windows 11 上编译、启动、测试通过；Windows 10 若没有实际设备，标记为“待兼容性验证”，不得宣称已通过。

**测试安全规则：** 先用测试用户或可恢复的 Windows 环境验证桌面图标变更。所有必要的系统级测试均需用户在本机明确操作或授权；不得破坏真实文件。自动化测试应优先对 Shell/注册项/窗口抽象层注入 Mock，减少对真实用户桌面的副作用。
