# Desktop Hub 完整体验改进规格

日期：2026-10-13（Asia/Shanghai）

状态：用户已认可上一轮建议并要求修改；本文件把方向落实为具体行为，待审阅后编写实施计划。

## 1. 目标与范围

目标用户是每天需要打开常用软件、组合工作场景和查找已有文件的 Windows 用户。此次优化的成功标准是减少寻找入口、滚动、逐项整理和理解执行依赖所需的操作，并让常驻成本与唤出速度可测量。

采用上一轮完整建议：八项体验改进、五项后续新增功能，以及常驻性能优化。后续新增功能安排在后续阶段实施，仍属于此次范围，不以仅完成前三项代替全部交付。

| 建议 | 本轮行为 |
| --- | --- |
| 统一搜索 | 一个入口搜索应用、场景、文件、文件夹、标签和项目；拼音首字母与键盘执行 |
| 紧凑布局 | 舒适 / 紧凑密度；缩短首页介绍与资源页头；折叠低频筛选 |
| 应用管理 | 原生拖入、拖动及键盘排序、扁平分组；复用现有批量发现 |
| 简单场景 | 批量选择应用；同时 / 顺序打开；简单模式的列表顺序就是实际调度顺序 |
| 执行结果 | 结果出现在操作附近；原因与修复入口；仅重试失败及被阻塞动作 |
| 批量文件整理 | 多选增减标签、收藏、接受同类建议；保存常用筛选 |
| Mini / Dock | 简化空分区；低频设置集中；启动后可选收起；收藏与固定独立 |
| 新手引导 | 先添加、启动和固定应用，再按需导入文件及设置常驻 |
| 最近使用 | 应用、文件、文件夹和场景的独立最近列表；不改变固定顺序 |
| 文件预览 | 图片缩略图、PDF 首页、空格预览及异常回退 |
| 开始菜单发现 | 个人 / 公共开始菜单快捷方式发现，与桌面来源统一去重 |
| 场景窗口布局 | 选择保存匹配窗口，运行后恢复位置、大小、显示器和最大化状态 |
| 项目集合 | 同一项目关联应用、场景、已授权文件 / 文件夹和网页 |
| 常驻性能 | 快速唤出 / 轻量常驻；隐藏界面释放及同条件性能比较 |

保留现有 18 DIP 圆角、四角透明、深浅与系统主题、不透明度、原生缩放、托盘、独立全局快捷键、全屏保护、自启及桌面图标恢复策略。文件仍留在原处；整理只写本应用元数据。

不增加账户、云同步、用户备份、配置导入导出或删除撤销。本轮项目集合是本地关联视图，不成为另一个文件存储系统。

## 2. 现状与基线

- 当前工程使用 C# / .NET 8 / WPF / WebView2，正式界面位于 `desktop/`，复用 `prototype/` 基础资产，不整体重写技术框架。
- Git HEAD 为 `9812df0`，当前分支为 `main`。当前工作区还包含既有未提交的应用导入改动，这些改动属于实现基线，应完整保留。
- 设置 schema 为 4，文件资源 schema 为 1。应用和场景以稳定 ID 引用；资源另存于 `resources.json`。
- 2026-10-13 已实现个人 / 公共桌面 EXE、LNK 自动发现、自选目录递归、最多 100 项批量添加、重复与失效提示及真实图标。新增入口复用这条导入通道，不再实现另一套桌面扫描。
- 顶部搜索当前面向资源，应用有独立搜索；普通资源页尚无批量整理，应用排列主要通过箭头完成。
- 场景已有调度与明确依赖，但高级列表排列仅影响显示；执行结果当前追加在页面末尾。
- 当前应用收藏通过 `PinnedToDock` 表达，必须新增独立收藏状态；不能迁移时移除已有 Dock 入口。
- 现有引导先导入文件来源，隐藏界面使用挂起，尚无用户可选择的释放模式。
- `docs/Resource_Usage_History.md` 的 M1 数据仅作历史参考。本轮需在产品代码修改前测量当前工作区发布版本，不将历史 M1 或旧 M2.2 当作当前性能基线。

本规格取代 `2026-10-12-desktop-hub-usability-design.md` 作为此次实施依据。旧文件保留为历史，尤其其中的收藏自动加入 Dock、单文件添加现状和旧性能基线不再适用。

## 3. 结构与交付顺序

采用在现有宿主上增加职责明确的服务、逐步调整现有界面的方案。仅改界面不足以支持批量原子提交、窗口布局和受限预览；整体重写会扩大兼容风险。

| 阶段 | 可验收交付 | 前置条件 |
| --- | --- | --- |
| A | 设置迁移、统一搜索、界面密度、批量文件整理、保存筛选 | 保留并验证当前基线 |
| B | 拖入 / 排序 / 分组、收藏与固定分离、开始菜单发现、简单场景、结果与重试、Mini / Dock、新手引导 | A 的公共交互与存储扩展 |
| C | 最近使用、图片与 PDF 预览、项目集合，并接入统一搜索 | A 的结果模型与 B 的动作反馈 |
| D | 场景窗口布局、轻量常驻、性能比较与发布验收 | B 的场景结果及 C 的可取消预览 |

各阶段保留可运行版本及验收证据；完成一阶段不代表整个请求完成。实施计划在本规格审阅后确定任务顺序和执行方式。

## 4. 寻找与整理

### 4.1 统一搜索

顶部搜索和 `Ctrl+K` 打开同一搜索面板，不清空原页面。输入立即获得焦点；上下键选择、Enter 执行、Esc 关闭并恢复原焦点；中文输入法组合期间不执行回车或方向键动作。

搜索覆盖已登记应用、已保存场景、已索引文件 / 文件夹、正式标签及已创建项目。网页通过所属项目的链接显示；不额外扫描磁盘。筛选类型包括全部、应用、场景、文件、文件夹、标签、项目。

结果携带类型、稳定 ID、名称、次要说明、可用状态及默认操作。同名结果以类型、路径或场景动作数区分。应用启动；场景执行；文件打开；文件夹进入库内浏览并提供资源管理器入口；标签进入对应筛选；项目进入项目详情。失效资源提供重新关联，停用场景提示启用，不把无效项作为默认可执行结果。

匹配按完整名称、前缀、名称包含、拼音首字母、登记路径和资源标签排序，同等分数维持稳定顺序。中文首字母依赖随应用分发的本地数据并保留许可证，多音字可有多个首字母匹配，不调用在线接口。

输入防抖 150ms，取消或忽略旧请求；单次最多 50 项，显示加载、无结果、失败及重试入口。1 万已索引资源下，最后一次输入到首屏结果的 p95 目标为 300ms 内，报告真实结果，不将目标写成已达到。

### 4.2 密度与首页

新增“界面密度：舒适 / 紧凑”，默认紧凑，持久保存；控制留白和行高，不整体缩小字体，紧凑正文不小于 13px。焦点、控件标签和操作区域保持清楚。

首页依次呈现常用应用、固定场景 / 项目、最近使用和工作模块。欢迎语缩成短说明；应用较多时场景与模块仍可通过固定导航直接到达。最近使用保持独立，不动态重排固定入口。

文件库压缩标题和主要操作区域，将来源与未选筛选折叠。已选条件始终可见，可逐个移除或清空。多标签默认同时满足，界面写明含义；筛选在分页前处理。保留页面、筛选、目录、页码和滚动的返回 / 前进恢复。

### 4.3 批量整理与保存筛选

资源库、收藏页和资源搜索结果提供选择模式；“选择本页”只选当前页，最多 500 项，可跨页保留。更换查询、来源或主页面清空选择；后台刷新仅剔除已经不可操作的选择，并提示数量变化。

批量添加 / 移除标签、收藏 / 取消收藏、接受同名同类型建议均为增量操作。提交前显示数量和影响；宿主验证全部 ID 后一次原子提交，写入失败或无效请求不留下部分变更。正常资源和失效索引清理的选择与操作严格分开。

保存筛选包含名称、查询、标签、扩展名、收藏条件和排序，不包含选择、页码或临时授权。重启可复用；已删除标签显示条件失效并允许编辑，不静默扩大匹配范围。

## 5. 应用、场景与入口

### 5.1 应用拖入、分组与开始菜单发现

保留现有桌面扫描、自选目录、手动选文件、桌面位置提示偏好和 100 项导入上限。手动选择支持多选，拖入 EXE / 普通 LNK 使用 WPF 原生文件拖放捕获，沿用短期候选令牌、确认和重验机制；前端不得凭任意路径字符串取得启动权限。

“添加应用”增加“开始菜单”来源，使用当前用户和公共开始菜单的 Programs 目录，递归查找普通 LNK。来源分别标注，重复按有效 EXE、参数及有效工作目录统一判断；不重复添加已经登记的桌面入口。沿用数量、深度、时间、联接 / 云占位跳过及不可读取目录提示。特殊 Shell / Store 快捷方式说明不支持，不误报为成功导入。

应用分组为扁平结构，可创建、改名、排序、移入 / 移出；应用只属于一个组，另有“未分组”。删除组只解除分组。拖动排序和键盘 / 箭头排序等价、重启保留；搜索期间关闭排序并解释清空搜索后可调整。各组内排序和组顺序独立，Mini / Dock 顺序也独立。

### 5.2 收藏与固定独立

`AppEntry` 新增独立 `Favorite`，`LauncherPin` 继续作为 Mini / Dock 固定的规范来源。收藏应用不自动添加或移除 Dock；固定入口不自动改变收藏。应用编辑页分别显示“收藏应用”“固定到 Dock”“固定到 Mini”。应用、资源、场景和项目的固定均只保存引用。

旧配置中 `PinnedToDock=true` 的应用迁移为收藏，同时保留已有 Dock 固定；其他应用不因升级自动固定。旧 `PinnedToDock` / `PinnedToMini` 保留为从固定关系推导的兼容字段，不再承载收藏。收藏页按应用和文件分区展示，搜索结果可筛选收藏，不把应用当作文件记录。

### 5.3 简单场景模式

新场景默认简单模式：名称、一次选择多个登记应用、同时 / 顺序打开、保存。可再增加网页、文件、文件夹；脚本和自定义依赖在高级模式编辑。

同时打开不建顺序依赖。简单顺序模式由当前列表生成前置完成依赖，拖动或箭头移动同时更新真实依赖；每步有编号，界面展示顺序含义。默认前一步启动请求提交后开始下一步；用户需要等待进程或窗口时通过高级设置明确指定，不能宣称程序已经加载完成。

原有场景迁移为高级模式，保留依赖。高级切换到简单模式前显示会被重建的设置并确认；简单切高级保留当前图与参数。高级排序继续只影响展示，并明确说明。循环依赖、无效目标和失效应用引用继续阻止保存；未保存草稿保留处理入口。

### 5.4 执行反馈与失败重试

结果使用当前视口内可折叠的面板，位于操作附近，不追加在任意页面底部。切换页面仍有正在执行的结果入口；Mini 显示进度，Dock 显示摘要。

分别表达请求已提交、已检测到进程、已检测到窗口和失败。技术代码、PID、原始诊断折叠。路径失效提供更换目标，依赖失败提供查看前置动作，执行结束可重试失败项。

失败重试基于原执行的场景快照建立新执行，仅重调度失败及被失败依赖阻塞的动作；成功 / 已跳过动作不重新启动。需要进程或窗口仍存在的依赖重新检查。脚本遵守会话重复策略，不用重试绕过该限制；重启后失去执行快照时不提供虚假的恢复入口。

### 5.5 Mini / Dock 和新手引导

空应用 / 场景分区缩为简短添加入口；图标大小和低频选项集中到设置。新增“独立应用启动请求成功后自动收起 Dock”，默认关闭；失败不收起，场景运行仍有进度入口。Mini 的 4 个入口上限保持。

引导改为欢迎 → 添加并尝试启动应用 → 固定入口 → 可选文件来源 → 常驻设置 → 完成。文件导入、桌面图标和开机自启为可跳过的选择，明确保留当前设置。启动程序只由用户点击触发，固定由用户明确选择，开始引导本身不执行这些动作。

已完成引导的用户不因升级强制重看；重新引导保留应用、资源、标签、收藏和系统偏好。保留个人 / 公共桌面位置提示的“不再提醒”偏好，不把此次体验优化当作理由重置它。

## 6. 最近使用、预览与项目

### 6.1 最近使用

记录成功提交的应用启动、文件 / 文件夹打开和已建立的场景执行。同一类型与 ID 去重更新时间，最多 50 项；首页最多 6 项，完整列表可清空。失败、搜索、悬停和预览读取不记录。

只保存类型、ID、时间、简短结果，名称与可用性取自当前实体。删除的实体不可通过历史旧路径继续执行，失效实体提供修复。历史不自动运行，不影响固定顺序。

### 6.2 图片和 PDF 预览

已授权、有效且可读资源支持 PNG、JPEG、BMP、GIF、WebP 静态预览及 PDF 首页。选中单项后空格打开、Esc 返回原选择；在输入框中空格仍作输入。其他格式提供元信息与外部打开入口。

使用原生限额解码和 Windows PDF 首页渲染；前端只接收受控图像，不任意读取本地 URL。当前工程已使用 Windows 10.0.17763 目标，PDF 投影、运行时和真实文件渲染仍须在离线环境实际验证。

只加载可见缩略图，解码并发最多 2；切换、离页或隐藏时取消旧请求。缩略图内存缓存上限 32 MiB，单个预览解码预算 16 MiB；图片最长边 1600、PDF 首页 1200 像素。缓存包含资源 ID、路径、修改时间和渲染规格，并在文件变化、重新关联及来源移除时失效。

不为预览主动下载云占位内容。损坏、加密、被移动或不支持的文件提示原因并可外部打开，不阻塞列表。

### 6.3 项目集合

新增项目列表和详情，项目包含稳定 ID、名称、简短说明、显示顺序及有序关联项。一个项目可关联已登记应用、场景、已索引文件 / 文件夹和 HTTP / HTTPS 网页；同一实体可被多个项目引用。新增实体继续通过既有应用导入、来源授权或网页地址验证流程。

项目详情按应用、场景、文件、网页展示，支持添加、移除关联及排序；点击关联项执行该实体已有操作。项目删除只移除项目及关联，不删除应用、场景、标签或实际文件。

项目本身只打开详情，不一键启动全部关联项，以免文件和网页被意外批量打开；需要组合启动时添加已有场景。应用 / 场景被删除或资源失效时保留“关联失效”提示，可移除或重新选择，引用不产生旧路径权限。

项目可固定到首页并从统一搜索找到。Mini / Dock 此轮仍以应用和场景为启动目标，避免改变已有入口语义。

## 7. 窗口布局与常驻性能

### 7.1 场景窗口布局

“保存当前布局”列出与场景登记应用匹配的可见顶层窗口，由用户选择。跨启动身份使用应用 ID、有效 EXE 和可选标题条件，不保存 HWND / PID 当作长期身份。保存显示器标识、工作区相对位置 / 尺寸及正常 / 最大化状态，并统一处理 DPI。

可选运行场景后恢复布局，也可手动恢复当前窗口，窗口等待默认最多 15 秒。多个候选且无法唯一匹配时让用户选择，不移动任意同名窗口；自身、系统、全屏和不可控高权限窗口跳过并说明，不自动请求提权。

显示器缺失则回退当前工作区并钳制可见范围。分别汇总启动和布局结果；部分布局失败不伪装为成功。验证正常 / 最大化、不同 DPI 双显示器及显示器移除。

### 7.2 轻量常驻与比较

新增“性能模式：快速唤出 / 轻量常驻”，默认快速唤出。保留共享 WebView2 环境、Dock / Workspace 懒创建和必要 Mini 入口。

轻量模式隐藏后取消预览与无用页面查询；60 秒后释放隐藏 Dock / Workspace 的界面对象，重新唤出重建并恢复导航、筛选、滚动和宿主状态。文件选择器、未处理草稿、导入确认或写入期间禁止释放。宿主场景执行和资源监测不因释放界面停止。

按实际交互状态降低无用轮询，但不牺牲边缘触发和全屏保护；悬停延迟误差作为验收条件。不得通过强制清空工作集制造性能改善结论。

代码修改前记录当前工作区的发布构建、源码状态、运行时与配置。优化前后相同条件测量首次 Mini、Dock、Workspace、返回 Mini 并等待释放后的进程组私有提交内存、CPU、进程数，以及冷 / 热唤出 p95。使用后 Mini 内存降低 20% 为目标，不是预先保证；如未达到，报告实测与原因，保留完整原始证据。

## 8. 数据与接口

设置升为 schema 5，资源升为 schema 2，最近使用和项目文件各使用 schema 1。项目独立存储，保存引用不复制实体配置；最近使用最多 50 项。

settings schema 3 / 4 与 resources schema 1 按已知结构幂等升级，保留稳定 ID、顺序、场景依赖、资源关系、时间标签偏好、系统状态、透明度和应用导入提示偏好。新增独立收藏的迁移按 5.2 节执行。未知版本保留原文件并停止写入。

| 边界 | 职责 |
| --- | --- |
| 搜索服务 / 面板 | 索引实体、匹配排序、取消旧查询、键盘选择、按 ID 调用已有操作 |
| 应用导入 / 分组服务 | 复用发现令牌；原生拖放 / 选择；统一去重；分组与排序 |
| 资源批量服务 | 验证全量参数、一次元数据提交、保存筛选 |
| 场景服务 | 简单模式构图、保留高级图、快照重试、可达结果反馈 |
| 最近使用 / 项目服务 | 有限历史、有序稳定引用、失效关联解析、原子存储 |
| 预览服务 | 授权解析、限额渲染、取消与缓存失效 |
| 窗口布局服务 | 枚举、唯一匹配、捕获、DPI / 显示器适配、恢复结果 |
| 窗口生命周期 | 隐藏取消、释放与重建、会话状态、性能测量 |

桥接沿用白名单和严格字段、长度、数量校验。新增搜索、批量整理、分组、最近使用、项目、预览、失败重试和布局消息，使用稳定 ID 或短期令牌；不开放任意命令执行或任意文件读写。

仅 Workspace 编辑与导入；Mini / Dock 调用启动及查看。宿主验证权限和边界，不能仅靠前端控件限制。删除关联、来源失效和数据变化都必须使缓存与可执行状态同步。

## 9. 验收与交付

- 在独立测试数据中验证迁移、重启与故障路径，正常用户配置不作为测试夹具。既有核心、场景、资源、系统、生命周期和前端测试继续通过。
- 搜索验证同名异类、拼音首字母、输入法、空结果、旧响应竞争、失效实体、键盘和焦点恢复。
- 批量整理验证跨页、切换清空、增量标签、建议类型、无效 ID、原子写入与重启筛选。
- 应用验证桌面 / 开始菜单统一去重、不可读取来源、特殊快捷方式、原生多选 / 拖入、过期令牌、分组与排序持久化。
- 收藏与固定验证四种组合和旧配置迁移，保证已有 Dock 顺序与入口不丢失。
- 场景验证简单排序改变实际执行、同时执行、模式转换、旧高级依赖保留、草稿及失败重试边界。
- 引导验证先应用后文件、每个可跳过步骤、显式启动和固定、旧完成记录及桌面提示偏好。
- 最近使用和项目验证删除 / 失效引用、项目删除不影响实体、共享引用、重启、搜索及固定顺序稳定。
- 预览验证真实图片 / PDF、损坏 / 加密 / 云占位、取消、缓存上限及文件变化失效。
- 窗口布局验证唯一 / 多候选、正常 / 最大化、不可控窗口、双显示器不同 DPI 和断开显示器。
- 轻量模式验证重复释放 / 重建、忙状态保护、后台执行与监测持续、导航恢复及真实前后测量。
- 深浅主题、100% / 200% DPI、640×480 与 960×640 DIP 检查主要页面、搜索、结果、导入和预览；确认无任务阻断的横向滚动、遮挡、焦点丢失及圆角回退。
- 最终提供完整构建、发布目录、功能验收记录、截图、性能比较和真实平台限制。只有核对发布内容一致后才更新工作区启动入口。
