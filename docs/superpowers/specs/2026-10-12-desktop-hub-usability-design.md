# Desktop Hub 用户体验优化规格

日期：2026-10-12（Asia/Shanghai）

状态：待用户审阅；尚未进入产品代码实施。

代码基线：已保存的 `d8ddd82`（新手引导 UI 简化），Windows M2.3 / 0.2.3。2026-10-12 已将该新版合并回当前工作区，恢复原有圆角 UI 和启动入口。

## 1. 已确认的目标与范围

用户先要求只读评审，随后明确采用建议 1–6、8 及四项补充功能，排除第 7 项，最后指示“开始优化”。本规格承接该决定，将建议转成可实施、可验收的行为。

目标用户是希望快速打开应用、组合工作场景和整理已有文件的 Windows 桌面用户。成功标准是减少寻找入口、逐项整理和理解场景配置所需的操作。用户明确要求保留工作台原有的 18 DIP 圆角 UI；后续优化继续保留四角透明、深浅主题、不透明度和原生缩放行为。

| 已采用的项目 | 对应设计 |
| --- | --- |
| 1. 统一搜索 | 应用、场景、文件、文件夹和标签统一查找；键盘选择与执行；拼音首字母 |
| 2. 紧凑布局 | 舒适 / 紧凑密度；常用入口靠前；低频筛选折叠 |
| 3. 应用管理 | 多选导入、原生文件拖入、拖动排序、应用分组 |
| 4. 简单场景模式 | 批量选应用；同时打开 / 顺序打开；高级依赖保持可编辑 |
| 5. 执行反馈 | 操作附近的结果面板；技术详情折叠；重试失败项 |
| 6. 批量文件整理 | 多选加减标签、收藏、接受同类建议；保存筛选 |
| 8. Mini / Dock 效率 | 空分区折叠；设置集中；启动后可选收起 |
| 补充：最近使用 | 应用、资源、场景的最近使用记录 |
| 补充：文件预览 | 图片、PDF 首页缩略图与空格预览 |
| 补充：窗口布局 | 为场景保存并恢复所选应用窗口位置、大小和显示器 |
| 补充：轻量常驻 | 隐藏窗口资源释放；唤出恢复；同条件性能测量 |

第 7 项的用户备份、配置导入导出、恢复入口以及删除撤销均不新增。现有配置防损坏机制继续属于存储实现，不扩展为用户备份功能。

## 2. 当前代码认知

- 原生宿主是 C# / .NET 8 / WPF；三种窗口使用 WebView2。`desktop/index.html` 复用 `prototype/` 基础脚本，正式业务由 `desktop/` 覆盖。
- `AppSettings` 当前 schema 为 4，包含应用、固定入口、场景与系统集成偏好；资源库另存 `resources.json`，schema 为 1。
- `desktop/desktop.js` 管理应用与 Mini / Dock 入口；`desktop/scenes.js` 管理场景；`desktop/resources.js` 管理资源。
- 顶部搜索转到资源搜索页；应用搜索独立；资源标签已按分类筛选并支持扩展名筛选，暂无常用筛选和普通资源多选操作。已有返回 / 前进导航、筛选与滚动恢复和应用收藏加入 Dock。
- 应用选择器每次选择一个 EXE / LNK，排列通过箭头完成。
- 场景显示顺序与依赖分离；“按列表顺序执行”会生成依赖，但随后移动列表不改变依赖。执行结果追加在内容区末尾，记录限于当前会话。
- 隐藏 WebView2 会尝试挂起，但实例仍保留；当前代码没有用户轻量模式。
- 最初调查时工作区切到了旧版 `main`，其源代码和启动快捷方式均为 M2.2；完整 M2.3、新手引导及圆角实现保存在 `codex/m23-windows-integration`。已恢复该保存版本及其 `win-x64-onboarding` 启动入口。后续以恢复后的新版为基线，保留托盘、全局快捷键、全屏保护、自启和桌面图标控制，不再使用旧版覆盖新版。

## 3. 实现方向与分期

考虑了三个方向：只优化现有界面、在现有宿主增加独立服务、整体重写界面与宿主。采用第二种：保留启动和文件授权通道，为搜索、最近使用、预览、布局管理增加明确边界；界面延续现有配色和图标。

整体重写会扩大风险；只改界面不能完成批量事务、可信文件导入、窗口布局和资源释放。本规格按四个阶段组织，每阶段有完整验收结果，后续阶段仍属于已采用范围。

| 阶段 | 用户交付内容 | 依赖 |
| --- | --- | --- |
| A | 统一搜索、密度、批量整理、保存筛选 | 现有应用 / 场景 / 资源库 |
| B | 批量导入、拖动与分组、简单场景、结果面板、重试、Mini / Dock 改进 | A 的公共交互与存储扩展 |
| C | 最近使用、图片和 PDF 首页预览 | A 的统一结果对象；B 的启动反馈 |
| D | 场景窗口布局、轻量模式与测量 | B 的场景结果；C 的可取消预览 |

本文件是功能与行为规格；实施任务、具体测试位置和执行方式在规格批准后的实施计划中确定。

## 4. 阶段 A：寻找与整理

### 4.1 统一搜索

顶部搜索和 `Ctrl+K` 打开同一搜索面板，保持原页面状态。输入立即获得焦点；Esc 关闭面板并回到原焦点；方向键选择结果，Enter 执行选中项。

搜索覆盖已登记应用、已保存场景、已索引文件 / 文件夹及正式标签，不扫描未授权目录。标签结果进入对应资源筛选；应用结果独立启动；场景结果执行场景；文件结果打开；文件夹结果默认进入库内浏览，并提供资源管理器入口。

结果对象统一携带实体类型、稳定 ID、显示名称、次要说明、可用状态和明确操作。类型分组可切换“全部 / 应用 / 场景 / 文件 / 文件夹 / 标签”。同名结果显示类型和路径或动作数量，避免误操作。

匹配顺序为完整名称、名称前缀、名称包含、拼音首字母、已登记路径及资源标签。已停用场景和失效资源可查到，但呈现停用 / 修复动作，不能伪装可启动。中文首字母使用随应用分发的本地数据，保留许可证；不依赖网络接口。多音字允许多个首字母匹配，搜索排序保持稳定。

输入防抖 150ms，每次请求带序号，旧响应不得覆盖新查询。单页最多 50 个结果；加载、空结果和失败都有可理解的提示与重试入口。1 万已索引资源条件下，从最后一次输入到首屏显示的 p95 目标为 300ms 内，单独报告实测结果。

### 4.2 密度与导航

设置新增“界面密度：舒适 / 紧凑”，默认紧凑，持久保存。控制间距和行高，不整体缩小字体；紧凑模式正文不小于 13px，键盘焦点和点击区域保持清楚。

首页优先显示常用应用和固定场景，其次是工作模块；缩短欢迎说明与装饰性标题。应用列表较多时首页仍有明显的场景与模块入口。

资源库将标题、数量与主要操作并入短页头，来源管理折叠，未选择的标签分类及筛选放进“筛选”区域。已选条件始终可见、可逐个移除，也可清空。增加扩展名筛选，组合条件在分页之前处理。多标签默认同时满足，界面写明“同时匹配”。

导航保留页面、搜索条件、临时浏览目录、页码和滚动位置；支持返回 / 前进及 Alt+方向键。离开未保存场景仍需处理草稿。640×480 DIP 和 960×640 DIP 下主任务不出现横向滚动；窄窗口的资源行保持紧凑，不把每行机械堆成大型卡片。

### 4.3 批量整理

普通资源页、收藏页及资源搜索结果增加选择模式。通过复选框多选；“选择本页”只选择当前页，界面显示已选数量。选项可跨页保留；切换查询、来源或主页面时清空，避免对不可见旧选择误操作。单次最多 500 项。

批量操作包括添加指定标签、移除指定标签、收藏 / 取消收藏，以及接受所选资源中同名同类型的待确认建议。加减标签是增量操作，不改动其他标签。提交前显示数量与目标标签；不打开实际文件。

原生服务先验证全部 ID、标签和建议，再使用一次资源存储更新提交。无效 ID、已删除来源、写入失败等情况下全部不提交，反馈错误并允许刷新后重试。查询结果变更与后台刷新不得改变用户滚动位置。

保存筛选包括名称、查询、所选标签、扩展名、收藏条件和排序，不保存所选资源或页码。重启后能重新打开；被删除的标签明确显示“筛选条件失效”，由用户编辑，不静默改变筛选含义。

## 5. 阶段 B：应用与场景

### 5.1 应用导入、排序与分组

应用选择器支持同时选择最多 100 个 EXE / 普通 LNK。批量导入先显示预览、重复和失败原因，用户确认后一次提交可用项；不导入的项单独汇总。相同目标及相同有效参数的入口视为重复，保留已有 ID、名称和固定关系。

从资源管理器拖入由 WPF 原生文件拖放接收；宿主验证文件并生成短期导入令牌，前端用令牌确认。前端不能凭任意路径字符串创建启动权限。现有 Store / 特殊快捷方式兼容边界仍以可验证能力为准，失败项给出具体说明。

应用通过拖动排序，键盘与现有箭头也可调整；搜索过滤期间不接受排序，提示先清空搜索。分组为扁平结构，每个应用属于一个组，可移到“未分组”；删除组只解除分组，不删除应用。Mini / Dock 的排列继续独立。

### 5.2 简单场景模式

新场景默认简单模式：填写名称、一次勾选多个已登记应用、选择“同时打开 / 按顺序打开”、保存。可再添加网页、文件和文件夹；脚本和自定义等待条件通过高级编辑配置。

同时打开不建立顺序依赖；顺序打开从当前列表生成明确的前置完成依赖。简单顺序模式中的拖动或上下移动同时重建顺序依赖，显示编号和连接提示。顺序的含义是前一步所设完成条件满足后再提交下一步，不承诺应用已经完成内部加载。

已有自定义依赖场景默认高级模式。切到简单模式前展示将被重建的依赖并明确确认；切换到高级模式保留全部动作和当前依赖。高级模式中移动仍只改变显示顺序，界面清楚提示。循环依赖、失效应用引用和无效参数继续阻止保存。

### 5.3 结果反馈与重试

Workspace 采用可折叠结果面板，处于当前视口可见区域，不追加到任意页面末尾。启动后展示场景名、进度、动作结果和下一步操作；Mini 显示进度入口，Dock 显示摘要。切换页面仍能找到正在执行的结果。

普通提示区分“启动请求已提交”“已检测到进程”“已检测到窗口”和失败原因。PID、内部代码和原始诊断进入详情。成功反馈可短暂显示，失败保留可操作入口。

“重试失败项”只针对已结束的本次会话执行。宿主保留原执行时的场景快照，以该快照建立新的执行记录；不读取后来修改后的场景并悄悄替换动作。成功和已跳过的动作不再次启动，失败及被失败依赖阻塞的动作重新调度。

已成功前置动作的完成结果可复用；要求进程 / 窗口仍存在的依赖需要重新检测，未满足则反馈，不假称成功。脚本遵守原有会话重复策略，违反该策略的重试需要单独显式选择。不能通过重试恢复上一次程序进程中已丢失的执行快照。

### 5.4 Mini / Dock

没有应用或场景时折叠对应空分区，保留一个简短添加入口。图标大小、显示密度等低频配置集中到设置，Dock 优先呈现启动入口。

新增“独立应用启动请求成功后自动收起 Dock”，默认关闭；失败时不收起。场景执行期间保持进度可达，自动收起规则不作用于场景。收藏应用加入 Dock 的规则在按钮提示与编辑页统一说明；Mini 固定仍独立管理。

## 6. 阶段 C：继续工作与预览

### 6.1 最近使用

记录成功提交的独立应用启动、文件 / 文件夹打开以及已建立的场景执行。失败请求、悬停、搜索和缩略图读取不进入历史。同一实体去重并更新时间，最多 50 项；只持久化类型、ID、时间和简短结果。

首页显示最多 6 项，可进入完整列表，并提供清空记录。名称、路径和可用状态读取当前实体；删除应用或资源后历史不产生可执行的旧路径入口。重启不自动执行任何历史条目。

### 6.2 文件预览

仅对有效、已授权、可读取的资源启用预览。支持 PNG、JPEG、BMP、GIF、WebP 的静态预览及 PDF 首页；其他类型显示元信息和打开入口。选中一项后空格预览，Esc 关闭并回到原选择；输入框中空格保持输入行为。

图片由原生解码生成受尺寸限制的位图；PDF 使用 Windows `Windows.Data.Pdf` 渲染首页。前端只接收宿主产生的受控图像，不用任意 `file://` URL 读取磁盘。PDF WinRT 投影 / 运行时兼容性需在当前离线构建环境验证，真实首页验收通过才算该功能完成。

缩略图仅为当前可见项目加载，不全库预生成；预览并发最多 2，切换项目、隐藏窗口及离开页面时取消旧请求。缩略图内存缓存上限 32 MiB，单个全尺寸预览不超过 16 MiB 解码预算，图片最长边 1600 像素，PDF 首页最长边 1200 像素。

缓存键包含资源 ID、路径、修改时间和渲染规格；文件变化、重新关联及来源移除后失效。云占位文件不因缩略图请求主动下载。加密 PDF、损坏文件、文件已移走或不支持解码时显示原因及外部打开入口，不影响列表使用。

## 7. 阶段 D：布局与常驻

### 7.1 场景窗口布局

场景增加可选布局记录。“保存当前布局”列出与场景已登记应用匹配的可见顶层窗口，由用户选择保存。识别使用应用 ID、有效 EXE 路径和可选窗口标题条件；不持久化 HWND / PID 作为跨启动身份。

每条布局记录保存显示器标识、工作区相对位置和尺寸、窗口正常 / 最大化状态；坐标明确转换为一致单位并处理 DPI。恢复显示器不存在时使用当前工作区并钳制可见范围，避免窗口落在屏幕外。

用户开启“运行场景后恢复布局”时，宿主等待对应窗口，默认最多 15 秒；可人工点击仅恢复当前已运行窗口的布局。成功启动不等于布局成功，结果分别汇总。

窗口匹配使用 exe 路径和标题条件。没有标题且同一程序有多个候选时，只在运行过程中明确取得唯一窗口的情况下自动恢复；其余给出选择入口，避免移动任意同名窗口。自身窗口、系统窗口、全屏窗口和不能控制的高权限窗口不自动调整；结果说明原因。实现不请求提权。

位置恢复使用 Windows 窗口 API，支持普通可移动窗口；验证正常窗口、最大化、两个不同 DPI 显示器及显示器移除情境。不可控窗口不以成功结果计入。

### 7.2 轻量常驻

设置增加“性能模式：快速唤出 / 轻量常驻”，默认快速唤出。保持共享 WebView2 环境和懒创建 Dock / Workspace。

轻量模式中隐藏窗口立即取消预览与页面查询；60 秒后可释放隐藏 Dock / Workspace 的 WebView2 控件和窗口，重新唤出时重建。Mini 保留。活动文件选择器、尚未处理的场景草稿、拖放确认或写入操作会阻止释放。

场景执行器与资源服务属于宿主，释放界面不终止场景执行或来源监测。重新打开时从宿主读取当前状态，恢复页面、筛选和滚动位置；会话中的场景结果仍可查看。

宿主检测定时器保持必要边缘触发能力；非交互空闲状态降低轮询频率，进入边缘后再提高频率。具体频率以不超过用户设置的悬停延迟误差为验收条件，不能为了数字降低而造成入口迟钝。

性能比较使用本轮未改产品代码的 M2.2 基线与本轮优化版本、相同运行时和设置。记录 Mini 首次、Dock、Workspace、返回 Mini 并等待释放后的进程组私有提交内存、CPU、进程数以及冷 / 热唤出 p95。使用后返回 Mini 的内存均值降低 20% 是目标，不是实施前保证；如未达标需写明实测值和原因。

## 8. 数据与接口边界

应用配置增加密度、性能模式、自动收起、应用分组、场景简单执行模式和布局信息；资源配置增加标签分类、常用筛选；最近使用作为有上限的独立活动数据，不复制可启动路径。旧设置与资源库按已知 schema 做一次幂等升级，保持 ID、标签、收藏、引用与固定顺序。

新配置明确使用 settings schema 5、resources schema 2，独立最近使用数据 schema 1。恢复后的源码有完整 settings schema 4 定义及既有迁移逻辑；settings schema 3 / 4 和 resources schema 1 按各自已知结构幂等升级，并保留 schema 4 的系统偏好与透明度等字段。其他未知版本停止写入并说明。所有新增字段都纳入规范化、克隆和存储校验。

新增服务边界如下：

| 服务 / 前端模块 | 职责 |
| --- | --- |
| 搜索服务 / 搜索面板 | 汇集实体索引、匹配和排序；键盘选择；按实体 ID 调用已有动作 |
| 应用批量导入服务 | 原生选择 / 拖放权限、预览令牌、重复判断和一次提交 |
| 资源批量服务 / 选择工具条 | 全量参数验证、一次元数据事务、保存筛选 |
| 最近使用服务 | 受限记录、去重、可用状态解析、清空 |
| 预览服务 | 授权路径解析、限额解码、取消、缓存和有效状态 |
| 窗口布局服务 | 窗口枚举、唯一匹配、显示器转换、布局捕获和恢复 |
| 宿主窗口生命周期 | 挂起 / 释放 / 重建；保存会话导航；性能测量 |

桥接沿用版本化请求 / 响应和白名单，新增搜索、批量整理、批量导入、最近使用、预览、重试、布局消息。请求使用稳定实体 ID 或短期令牌；每种消息有固定字段、数量和长度上限，不提供任意命令执行或任意文件读写接口。限制字段验证发生在宿主，不仅依赖前端。

仅 Workspace 接受编辑、批量整理、导入与布局配置；Mini / Dock 继续只调用启动与查看。预览和搜索任务必须可以取消，错误转成人话，技术细节可展开。

## 9. 验收标准

- 保留现有应用独立启动、场景调度、文件来源授权、修复和元数据存储行为；核心、场景、资源和前端原有测试通过。
- 统一搜索覆盖同名异类、中文首字母、空结果、旧响应竞争、失效实体、键盘路径及 Esc 焦点恢复。
- 批量整理覆盖跨页选择、切换条件清空、标签增量、重复建议、无效 ID 和写入失败的原子性；重启后常用筛选仍有效。
- 应用导入覆盖部分失败、重复、用户取消、拖入非 EXE / LNK、伪造或过期令牌；拖动及键盘排序后重启顺序一致。
- 场景覆盖同时 / 顺序模式、排序后真实执行顺序、自定义依赖切换、循环依赖和未保存草稿；失败重试不重复成功项或绕过脚本策略。
- 原生预览覆盖真实图片、真实 PDF 首页、损坏 / 加密文件、云占位、来源撤销、快速切换和缓存限额。
- 窗口布局用测试创建的无害窗口验证，不移动用户正在使用的窗口；多显示器实机能力与仅可自动化验证的部分分别记录。
- 轻量模式覆盖正在执行场景、页面释放后重建、草稿阻止释放、重复打开关闭以及退出释放；性能数字来自相同条件测量。
- 深浅主题、舒适 / 紧凑密度、640×480 与 960×640 DIP 做实际截图检查；无横向溢出、遮挡和丢失主操作；键盘焦点与读屏提示可达。
- 原生验收使用独立测试配置、受控应用和临时文件，不以个人资源库作为写入测试目标。
