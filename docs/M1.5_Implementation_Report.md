# Desktop Hub — M1.5 实施报告

日期：2026-10-10（Asia/Shanghai）　版本：0.1.5　依据：PRD v0.7.1。

本轮在已完成的 M1 架构和 UI 上增加独立常用应用库。应用和场景保持不同实体；用户直接点击应用图标启动一个程序。完整场景执行器与文件索引未开发。

## 1. 新版需求与原实现差异

先读取了 `PRD.md` 全文、M1 实施报告、桥接协议、现有 C# 与桌面适配、原型 UI 规格和测试。目录依然不是 Git 仓库。

| 新版要求 | M1 实际状态 | M1.5 最小扩展 |
| --- | --- | --- |
| 独立多应用库 | 一个可替换 `LaunchTarget` | `AppEntry` 列表和稳定 ID，每次添加追加 |
| 添加/编辑/移除/排序/搜索 | 仅选择及更换单个 EXE | 应用启动台、编辑对话框、管理模式与独立排序 |
| EXE 与 LNK、参数、工作目录 | EXE 无参数，目录固定 | 原生 LNK 读取、参数及目录校验、启动时重新校验目标 |
| 真实图标及统一回退 | 通用 SVG | 原生图标提取、本地 PNG 哈希缓存、通用 SVG 回退 |
| Mini 混合入口 | 原型场景和单目标入口 | 统一 `LauncherPin` 引用，最多四个可见入口 |
| Dock 常用应用区 | 单目标按钮 | 紧凑应用网格，独立场景区、排序和三档图标尺寸 |
| Workspace 完整启动台 | 单目标面板在场景中心 | 首页“我的应用”优先显示，点击即可启动 |
| 可靠本地持久化 | schemaVersion=1 原子 JSON | schemaVersion=2、事务更新、旧目标非破坏性迁移 |
| 后续场景复用 | 无独立应用实体 | 稳定 AppEntry ID、`FindById` 与 `LaunchApp` 接口 |

保留 WPF/WebView2、共享 Environment、三个独立 HWND、延迟初始化、隐藏挂起、前台恢复、边缘悬停、本地 origin、CSP 与受限消息通道。未引入新的前端框架或重建项目。所有已验收原型源文件保持原样。

## 2. 实现与数据关系

`AppEntry` 包含 `id/name/target/arguments/workingDirectory/icon/displayOrder/pinnedToMini/pinnedToDock`，补充 `entryKind=exe|lnk`。`target` 保存原始选择的 EXE 或 LNK，不复制到界面固定数据。

`LauncherPin` 包含稳定 ID、Mini/Dock 位置、app/scene 类型、实体 ID、顺序和可见状态。Workspace 的应用顺序、Dock 的应用/场景顺序、Mini 的混合顺序独立保存；取消固定不移除应用。布尔固定标志从对应位置 `enabled=true` 的应用入口引用同步。应用库没有一个或四个应用的条目上限，配置 UTF-8 序列化安全容量为 16 MiB。

`AppLibraryService` 用配置事务实现添加、编辑、替换目标、移除与排序。重复目标可以添加为不同配置；重复 ID 拒绝覆盖。应用启动只携带登记 ID，核心通过 `LaunchApp(settings, appId)` 读取对应配置；不自动生成场景，不采用场景的跳过重复进程规则。

M1 的旧目标只在 schemaVersion=1 时迁移，并沿用原稳定 ID；已有应用不覆盖，保留旧记录，写回 schemaVersion=2。再次读取不会重新新增，移除迁移项后也不会复活。失效但可识别的路径保留为可修复应用；不安全/不可识别旧目标保留在旧字段并记录原因。迁移写入失败不替换原文件。

所有真实应用记录、固定入口、图标引用、尺寸偏好仍保存在 `%LOCALAPPDATA%\DesktopHub\settings.json`。图标缓存位于同目录 `icons/`。应用业务数据不写进原型 localStorage；场景及资源演示继续与真实应用库分开。

## 3. 用户操作与视觉保留

UI/UX 检查遵守已有 Quiet Desktop 方向：普通 Windows 用户从 Mini 或 Dock 进入首页，先选择已保存应用或添加第一个应用；启动结果就在当前界面反馈，错误可通过编辑、更换文件或工作目录恢复。首页优先应用，其次场景和原有工作空间模块。沿用原有字体、主题 token、圆角、图标和按钮，不重设计整套界面；窄窗口适配现有桌面布局。

- Workspace：“我的应用”展示完整图标网格和搜索；“管理应用”显示编辑及排序工具。应用独立启动，不进入场景编辑器。
- 编辑：名称、参数、工作目录、Mini/Dock 固定；路径更换继续使用原生选择器。
- 移除：确认框说明只删除 Desktop Hub 记录，不删除文件、不卸载软件；移除应用固定引用，其他应用保留。
- 固定入口：Mini/Dock 分别管理、排序；Mini 允许最多四个应用/场景混合入口，无可用入口时显示“添加入口”。
- Dock：紧凑应用图标区与快捷场景区分开；图标支持紧凑/标准/较大，尺寸独立持久化。
- 错误：Workspace/Dock 显示实际原因；Mini 可展开简洁错误区域并关闭反馈。

场景入口继续标为原型演示，点击不会使用模拟成功声称真实组合启动。文件、标签等页面仍是原型边界。本轮没有扫描、移动或索引桌面文件。

本轮同时修正用户反馈的深色 Workspace 顶部浅色窄条：仅在 Workspace 使用 `WindowChrome` 将内容扩展至原生边框区，保留六像素边缘缩放命中区；原生窗口背景和 WebView2 空白背景随主题同步，Windows 11 的外侧细边框禁用绘制。Mini/Dock 透明宿主不改。验收增加包含原生窗口边框的真实截图和缩放命中检查，避免只看 WebView2 页面截图遗漏此问题。实现参考微软的 [WindowChrome](https://learn.microsoft.com/en-us/dotnet/api/system.windows.shell.windowchrome) 和 [DWM 窗口属性文档](https://learn.microsoft.com/en-us/windows/win32/api/dwmapi/ne-dwmapi-dwmwindowattribute)。

## 4. Windows 启动、安全与兼容范围

文件选择器仅允许用户主动选择本地 EXE/LNK，`DereferenceLinks=false` 保留快捷方式原路径。LNK 通过 COM 读取目标、参数、工作目录和图标位置，启动时重新读取并校验普通本地 EXE；不调用快捷方式目标搜索/修复，不改原 LNK。添加时导入的参数/目录成为应用记录配置；之后保存的空参数也覆盖 LNK 默认参数，空工作目录回退到最新解析 EXE 所在目录，LNK 目标以最新解析结果为准。编辑器更换目标保留原名称、参数及工作目录，可按需调整。

路径校验拒绝相对路径、UNC/网络盘、协议、设备路径和命令字符串；检查有效 PE 文件头，拦截已知命令与脚本执行宿主。参数拒绝控制字符并限制长度，直接传入 `ProcessStartInfo`，`UseShellExecute=false`；不执行 shell 文本，不设置 `runas`，普通用户权限运行。

图标由原生层提取并释放 HICON，按内容哈希保存 PNG；读取或提取失败回退同一通用图标。图标路径也先校验为本地路径，界面只接受缓存 PNG data URL，不使用外网图标。

启动成功表示 Windows 返回进程创建结果，不等于第三方软件完全加载。返回真实失效目标、目录错误、无权限、无效 PE、要求提权和系统拒绝启动等错误；不检测应用后续崩溃。本实现不是所选软件的安全沙盒。

Store/MSIX、特殊 Shell/网页/文件快捷方式、嵌套 LNK、Windows Installer 特殊快捷方式、提权启动、脚本等仍待独立兼容验证，不作为本轮已支持项。Windows 10、多显示器、其他 DPI、所有游戏保护及长期资源表现继续保留 M1 的待验证事项。M1 没有实现的真实全局快捷键、托盘、自启也未在本轮扩大范围。

当前协议接口及限制见 [M1.5_Bridge_Protocol.md](M1.5_Bridge_Protocol.md)。Windows 接口实现依据和微软文档链接一并记录在该文档。

## 6. 文件与复现方式

主要变更位于 `src/DesktopHub.Core/` 的模型、存储、校验、启动及新增应用库服务；`src/DesktopHub.Windows/` 的桥接扩展、新增快捷方式解析与图标缓存；`desktop/` 的应用 UI 及回归测试。原生验收新增 `scripts/test-m15-native.ps1`，旧 `test-native.ps1` 转发到新验收并保留 M1 历史证据。

```powershell
.\scripts\build.ps1 -Offline
.\scripts\test-m15-native.ps1 -SkipBuild -CoreFixtureIntegration
.\scripts\publish.ps1 -Offline
```

原生验收采用隔离 `m15-smoke-data`，通过真实文件选择器、DOM 点击、Windows PID/HWND、原文件哈希与第二个独立宿主进程验证；不改用户应用库。它会短暂移动鼠标、打开测试创建的系统 GUI 程序，并正常关闭这些测试窗口。

发布产物为 `artifacts/win-x64/DesktopHub.Windows.exe`（需保留相邻 UI、DLL、runtimes）。原有 `打开 Desktop Hub.lnk` 指向的发布目录继续使用。打开 Workspace 首页即可添加应用。实施仅止于 M1.5。
