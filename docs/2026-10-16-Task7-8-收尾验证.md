### 本次发现与修复

首次原生run在安全隐藏62秒后Workspace未释放。只添加截止诊断日志后的run `d81e7db7-08bc-46a7-a124-b94151356ae8` 36/0，不能据此称已修复。独立.NET8.0.17探针64次真实60000ms等待中10次按产品单调时钟仅经过59999ms；另一个25ms×200段没有提前，二者不可混算。证据 `2026-10-16-deadline-probe-system.log`。微软说明 [Task.Delay使用的系统时钟](https://learn.microsoft.com/en-us/dotnet/api/system.threading.tasks.task.delay?view=net-8.0) 与Stopwatch计时并非同一边界。

产品原先只尝试一次；若提前1ms醒来，安全策略拒绝释放且没有下一次计时。现将等待边界提取为 `HiddenSurfaceLifecycle.WaitForDeadlineAsync`，每次按剩余单调时间继续等待，保持60000ms、busy/snapshot、代际、可见性及宿主所有权检查。可控时钟回归先RED（未到截止后不能再释放），后正常权限Lifecycle15/0 GREEN，增加过期owner与唤醒时取消保护。该机制已被真实探针与确定性测试证明，但首次失败未记录deadline，不能宣称它是历史失败唯一可能原因。

用户指出实际Dock中两种空入口的加号尺寸/横向位置不一致。原场景使用文本 `+`，应用使用15px SVG，且应用另有不对称顶部padding。新增真实DOM几何检查先在run `ad634065-b6cc-4f05-bbba-298bcee48f15` RED，随后统一同一SVG及padding/gap/对齐规则。检查同时覆盖首次Dock和释放后重建，比较SVG尺寸、横向坐标、字级及按钮内垂直居中。最后run `e53b1774` 两次几何检查GREEN，修复后的 `rebuilt-dock.png` 已查看。

## File.Replace 调查与有界恢复

早期完整脚本在正常权限通过，但后续旧版cold run `14665cae-5444-466c-9d04-056ddebc2f50` 在3个成功样本后启动失败；候选quick run `9cc67585-a945-4d71-a2ab-255b4f8084d4` 在5个成功后也失败，均为SettingsStore.Save。两批均不作为完成冷20或当前p95，不循环重跑到绿。此证据排除了“只有沙箱才发生”的解释。

`2026-10-16-settings-trace.json`：用旧Core、.NET8.0.17、测试GUID目录，2000轮复刻“Prepare保存布局版本0→新store.Load→保存版本1”，13次非控制异常均为HResult80070497 / Win321175。first-chance回调随即尝试DELETE打开均成功，Restart Manager未报告持有者；正控制FileShare.Read锁返回32、DELETE失败且正确找到本Trace进程，证明探针可区分普通稳定共享锁。不能据此排除失败之前的瞬时持有者或过滤驱动，也没有确定底层原因。

诊断用仅1175、20/40ms有限重试：另2000轮实际23次1175均恢复，外层未恢复0（`settings-trace-recovery.json`）。[Microsoft ReplaceFileW文档](https://learn.microsoft.com/en-us/windows/win32/api/winbase/nf-winbase-replacefilew)明确1175保留双方原名，而1176/1177可能改变名称状态。基于这个可重试边界，新增内部AtomicFileReplacement供Settings/Resources/ActivityProject三处原子提交共用：仅exact1175重试同一File.Replace、总共最多3次；额外请求等待20+40ms，不是墙钟硬上限；其他错误原样抛出，不改Move/Delete/Copy，不开放非原子覆盖。原有锁、校验、临时文件清理及成功后更新Current顺序保留。

新增回归先在原one-shot提取行为上RED：1175恢复、有界终止两项失败；修复后Core68/0，另含拒绝重试5/32/1176/1177/其他错误。直接加载修复后Core、没有探针外层重试的2000轮再现21次1175，全部内部恢复，外层失败0（`settings-trace-fixed.json`）。独立规格/质量窄复审PASS。这是有证据的有限恢复，不声称底层驱动问题已定位或任何持久故障永远不失败。
