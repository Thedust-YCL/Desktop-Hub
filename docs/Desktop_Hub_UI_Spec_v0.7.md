# Desktop Hub — UI 设计交接规格 v0.7

> **用途**：提供给 Codex 的可执行 UI 设计依据。此文档是聊天中 Mini / Dock / Workspace 视觉概念的文字化交接稿，不是已有的 UI 源代码或可直接运行的设计稿。
>
> **阶段**：M0 高保真可交互原型。**本阶段不开发 Windows 原生集成，也不修改用户系统设置或文件。**
>
> **优先级**：六轮确认的产品行为 > 本文的具体设计初值 > Codex 的实现习惯。本文“建议”可以在不违背确认需求的前提下微调。

## 1. 产品目标与设计原则

Desktop Hub 是 Windows 本地离线桌面集成工作空间：以极简入口实现一键多程序场景启动，并对分散在桌面与其他授权位置的文件建立**虚拟索引、标签与收藏**关系。用户不想按传统方式重新整理桌面，因此产品不可强迫移动文件。

界面方向：**Quiet Desktop / Minimal Desktop × Fluent Design × Modern Dock**。

- 低饱和、克制的半透明、简洁几何构图、适度圆角、明确的信息层级。
- Mini 和 Dock 尽量低干扰，Workspace 内容可读性优先；不要把整套界面做成高强度毛玻璃特效。
- 三种状态属于**同一个应用**，数据与设置共享。
- 应用无账户、无远端数据库、无强制联网。M0 的模拟数据不代表真实系统数据。
- 将功能丰富度集中于 Workspace，而不是在 Mini 或 Dock 堆砌信息。

## 2. 已确认的界面行为（不得擅自更改）

| 对象 | 已确认需求 |
|---|---|
| Mini | 半透明细长工具栏；默认显示 **2–4 个用户固定的场景图标**；首次可选位置，设置可调整位置、尺寸、模式；点击图标直接启动场景（M0 模拟）。 |
| Dock | 屏幕边缘悬停约 **500ms** 展开；可自定义位置、大小；普通程序位于前台时也可唤出；全屏游戏和屏蔽程序除外；运行结束不自动收起。 |
| Workspace | 全屏或近全屏的 **Launchpad 启动台**；首页以常用功能入口为主；从普通软件快捷键唤出时临时覆盖，按 **Esc** 关闭并尽可能返回之前的应用。 |
| 触发方式 | Mini、边缘悬停、独立 Dock 快捷键、独立 Workspace 快捷键，允许在设置切换/组合。 |
| 主题 | 默认**跟随 Windows 明暗主题**；原型演示中允许手动切换深色/浅色以评审两套设计。 |
| 动画 | 短促、克制，提供关闭动效的设置；隐藏时减少无意义动画。 |
| 性能优先 | 文件库首版**只用文件类型图标**，不解码图片、不渲染 PDF 文档缩略图。 |
| 场景反馈 | 状态为待执行、执行中、成功、跳过、失败；失败反馈简洁；场景运行后不强制自动关闭面板。 |

**重要技术边界**：视觉上融入桌面≠必须嵌入 Windows 壁纸层。真正桌面层级、全屏游戏识别及前台焦点恢复留待技术验证，M0 以视觉+交互模拟表现，不声称已经实现操作系统能力。

## 3. UI 视觉设计 token（建议初值）

### 3.1 深色主题

- 页面底色 `#111A23`
- 面板底色 `#1C2A36`
- 浮层 / 次级表面 `#2B3E4F`
- 强调色 `#92B6D1`
- 主文字 `#E7EFF5`
- 次级文字建议 `#A7B8C6`

### 3.2 浅色主题

- 页面底色 `#F1F4F6`
- 面板底色 `#FFFFFF`
- 次级表面 `#DEE6EC`
- 强调色 `#527F9E`
- 主文字 `#253441`
- 次级文字建议 `#657787`

### 3.3 尺寸与动效

- Mini 横向或纵向细长工具栏，厚度参考 `48–56` 逻辑像素；方向取决于固定边缘。
- Dock 紧凑宽度参考 `68–88` 逻辑像素，展开区按内容自适应。
- 卡片圆角 `12–16`，布局采用 `8 / 12 / 16 / 24` 间距体系。
- 主要字号 `14–16`，大标题 `24–30` 逻辑像素。
- 过渡动画建议 `150–220ms`，支持 `prefers-reduced-motion`。
- 避免荧光色、复杂纹样、高饱和色块、大面积强烈阴影或过量玻璃模糊。
- 图标使用**统一的 SVG/图标集**，不要混合多套风格；不依赖远程 CDN。
- 注意不同 DPI 与不同屏幕宽度；M0 主要模拟单显示器 Windows 桌面。

**这些为原型设计建议值，不是冻结的技术指标。**

## 4. 页面地图与信息架构

```text
Desktop Hub
├─ Mini（常驻、2–4 固定场景）
├─ Dock（场景快速启动、进度提示、Workspace 入口）
└─ Workspace（Launchpad 首页）
   ├─ 场景中心 Scene Center
   │  ├─ 场景列表 / 添加 / 修改 / 删除 / 排序 / 固定 Mini
   │  └─ 场景编辑器（动作列表 + 动作配置 + 执行反馈）
   ├─ 文件资源库 Resource Library
   │  ├─ 列表视图
   │  ├─ 图标网格视图（非缩略图）
   │  ├─ 标签视图
   │  ├─ 文件夹临时浏览
   │  └─ 失效资源中心（Missing、PendingRepair、SourceUnavailable）
   ├─ 标签中心（主题 / 时期 / 自定义）
   ├─ 收藏中心
   ├─ 快速搜索（文件名、标签）
   └─ 设置
      ├─ 外观与主题
      ├─ Mini / Dock 位置、尺寸、触发
      ├─ 快捷键（Dock 与 Workspace 分开）
      ├─ 全屏保护与排除程序
      ├─ 索引目录（个人桌面默认、公共桌面可选、自定义目录）
      ├─ 开机自启 / 托盘
      └─ 桌面图标隐藏及恢复策略
```

## 5. Mini 页面规格

- 默认三个示例固定场景：创作、游戏、休闲；此为假数据，用户实际可固定 2–4 个自定义场景。
- 半透明的细长几何形态，优先只显示统一风格图标，通过悬停 tooltip 展示名称。
- 当前场景可有轻微选中或运行中状态，不展示大段文字。
- 点击固定图标触发模拟启动反馈；可以从 Mini 进入 Dock/Workspace。
- 初次无场景时显示“添加第一个场景”的空状态，不应出现无法使用的硬编码启动动作。
- 演示 Mini 的位置变化：左 / 右 / 顶部，至少一个可切换的示例。

## 6. Dock 页面规格

- 边缘触发停留约 500ms，悬停离开行为避免闪烁；移动到展开 Dock 内不得立刻收起。
- 面板以 2–4 个常用场景为重点，可以查看更多场景；包含 Workspace 入口。
- 示意场景：
  - **创作**：加速器 → Clash → ChatGPT → Edge → DSH（实际调度用户定义）。
  - **游戏**：示例内容，由用户自定义。
  - **休闲**：示例内容，由用户自定义。
- 每个入口包括图标、名称、必要的简短说明、启动按钮或整卡可点区域。
- 场景状态可显示一个小型进度条、状态文本，失败提示不淹没正常内容。
- 运行后保持 Dock 展开，直到用户主动关闭/切换。
- Dock 独立快捷键与 Workspace 独立快捷键需在演示控制层体现；原型允许用不冲突的示例快捷键和控制按钮模拟。

## 7. Workspace / Launchpad 首页规格

- 全屏 / 近全屏布局，有品牌标识、搜索入口、设置入口和关闭入口。
- 首屏以六个 **统一规格的常用功能卡片**为主：
  1. 场景中心
  2. 文件资源库
  3. 标签中心
  4. 收藏
  5. 快速搜索
  6. 设置
- 深浅主题各有完整样式。
- 卡片内容精简，足够大的点击区域，hover/focus 状态一致。
- Esc 关闭 Workspace，演示视觉上“回到之前的 Edge/普通应用”（不需要也不能在浏览器网页原型中真正切换 Windows 前台进程）。
- 二级页提供清晰返回 Launchpad 的入口；不要将所有业务表单放在首页。

## 8. 场景中心与场景编辑器

### 场景中心
- 场景列表卡片显示图标、名称、动作数量、启动按钮、编辑入口、固定到 Mini 状态。
- 支持新增、重命名、调整顺序和删除等**原型级操作**，仅修改本地模拟数据。
- 点击启动可运行**模拟进度**并展示成功、跳过、失败样例。所有反馈必须显式标注为“模拟”。

### 场景编辑器（推荐左右结构）
- **左侧**：可排序动作列表。每条有序号、类型图标、名称、执行概况、拖拽手柄。
- **右侧**：当前动作的参数区：动作目标、运行方式、依赖、等待类型、延时、超时、重复策略；高级参数可折叠。
- 普通编辑操作无需编写脚本；脚本动作是“选择已有文件”，不内建脚本编辑器。
- 支持动作类型：程序、网页、文件、文件夹、脚本。
- 执行方式：并行、顺序、固定延迟、等待进程、等待窗口；后两类默认超时 10 秒。
- 依赖失败：依赖动作跳过，独立动作继续。
- 程序已运行默认跳过；网页/文件每次执行仍可打开；脚本默认**同一次场景执行实例最多执行一次**，再次点击场景可重新执行。
- 必须表现循环依赖是不允许的；实际调度器留给后续阶段。

## 9. 文件资源库

### 9.1 三视图
- **列表**：文件类型图标、文件名、标签、收藏状态、状态。
- **图标网格**：统一文件类型图标 + 名称，无图片内容缩略图。
- **标签视图**：按主题、时期或自定义标签分组，文件可归属多个集合。

### 9.2 初始扫描和目录管理
- 首次默认当前用户桌面，扫描预览确认后才写入长期索引。
- 公共桌面可选，用户能新增其他授权目录；所有已授权目录未来自动监测。
- 文件夹默认不递归索引；个别目录可以开启递归索引。
- 非递归文件夹仍可在应用中临时浏览内容，也可通过资源管理器打开；临时浏览不等于已经索引。
- M0 中以上功能只模拟授权、扫描、增删，不要在真实电脑上遍历或改动桌面。

### 9.3 标签与建议
- 标签类型：主题、时期、自定义；多对多关联。
- 依据文件名、目录及文件**创建时间**提供本地规则建议。
- 建议标签展示在资源卡片内，支持接受、拒绝、编辑；**没有确认不能写入正式标签关系**。
- 示例：`设计参考图.png` 同时属于 `课程作业` / `设计素材` / `2026年10月`。

### 9.4 失效资源
- 状态：Active / Missing / PendingRepair / SourceUnavailable。
- 删除文件仍保留索引、标签与收藏；重命名可靠识别时更新路径；移动后由用户手动修复。
- 失效资源中心支持筛选、单项修复、批量清理**仅索引**。
- M0 只模拟修复和清理，不接触磁盘文件。

### 9.5 搜索与收藏
- 文件名搜索与标签筛选；收藏常用资源；卡片中模拟打开文件/定位文件的行为，必须说明为演示。

## 10. 设置界面

至少有以下可交互原型项：
- 外观：自动跟随系统 / 强制深色 / 强制浅色；减少动画、透明效果。
- Mini：固定场景选择（2–4）、位置、尺寸。
- Dock：位置、尺寸、悬停触发、500ms 延迟、是否允许在普通软件前台展开。
- 快捷键：Dock 和 Workspace 分开，处理冲突的提示。
- 游戏保护：全屏游戏保护说明、排除程序列表（原型模拟）。
- 文件来源：个人桌面默认、公共桌面自愿勾选、自定义目录及递归选项（原型模拟）。
- 系统：开机自启和托盘策略（原型模拟）。
- 桌面图标：首次启用隐藏时**必须先让用户选择退出后的恢复策略**；M0 只演示确认对话框，不真正隐藏系统图标。

## 11. 交互流程（必须能点通）

1. **首次使用**：欢迎页 → 桌面扫描预览 → 用户确认 → Mini 位置选择 → 进入 Launchpad → 创建第一个场景 → 固定 Mini。
2. **一键创作**：Mini 或 Dock 点击创作 → 模拟多动作进度（包含已运行跳过、失败样例）→ Dock 保持展开。
3. **场景编辑**：场景中心 → 新建/编辑 → 增加动作 → 设置等待/依赖 → 保存 → 返回并启动模拟。
4. **虚拟归集**：资源库出现新文件 → 展示建议标签 → 接受建议 → 在标签视图找到该文件；不改变原文件。
5. **失效修复**：失效中心 → 选择 Missing 项 → 模拟重新关联 → 标签与收藏仍保留。
6. **唤出返回**：模拟 Edge 等普通应用 → 唤出 Workspace → 按 Esc 返回模拟前台应用。
7. **桌面图标隐藏**：首次点击设置 → 告知影响 → 选择退出策略 → 确认（仅演示，无系统修改）。

## 12. M0 原型开发边界（严格）

**要做：**
- 真实可运行的、本地打开的高保真 UI 原型，非静态图片。
- 完整 Mini、Dock、Workspace 主页面及上文关键二级页面。
- 深色/浅色适配、状态切换、视觉反馈、模拟场景及文件数据。
- 交互可点击，部分模拟数据可用本地浏览器存储持久化；提供重置演示数据。
- 适应桌面端常见窗口尺寸，设置基本键盘导航、焦点态和 Escape 行为。
- 完整的使用说明与交互验收清单。

**不要做：**
- 不调用真实进程、不启动实际程序或脚本。
- 不扫描、监控、移动、删除或修改真实桌面文件。
- 不实际隐藏 Windows 桌面图标，不注册真实系统级快捷键。
- 不替换 Windows Shell、不尝试 WorkerW 等非公开壁纸层嵌入。
- 不做账号、后端、联网请求、云服务、AI 自动分类。
- 不急于决定最终 WPF / WinUI 3 / Tauri 技术栈；UI 原型可独立进行，原生能力单独做技术验证。

## 13. 给 Codex 的建议实现方式

如果当前仓库没有技术栈，**建议先用离线 HTML + CSS + 原生 JavaScript** 完成 M0 UI 原型（可在普通浏览器打开），便于评审视觉、布局和交互。若仓库已有现成技术栈，先读取现有结构，避免无依据地覆盖或重构。

推荐代码组织（仅当新建原型时）：

```text
DesktopHub/
├─ docs/
│  └─ Desktop_Hub_UI_Spec_v0.7.md
├─ prototype/
│  ├─ index.html
│  ├─ styles.css
│  ├─ app.js
│  └─ assets/
└─ README.md
```

完成后运行最少一轮交互自测：切主题、切三状态、进入六个模块、编辑场景模拟、接受标签建议、失效资源模拟、Esc 返回、重置演示数据。

## 14. 验收与交付

- 页面视觉统一，无无效装饰或大量 placeholder；文本不溢出、不重叠。
- Mini 有 2–4 固定场景；Dock 约 500ms 悬停触发；Workspace 是 Launchpad 首页。
- 主要按钮可交互，不是只有 hover 效果的静态外壳。
- 深浅两套主题完整且可读；系统主题跟随为默认模式。
- Demo 不产生真实操作系统副作用，任何“启动成功”都明确写为模拟。
- 关键流程全部可从界面完成，复杂配置不堆在首页。
- Codex 完成时列出新增/修改文件、启动方法、已验证流程、未完成事项；提供至少一份原型效果截图（若本地环境具备截图工具）。

---

**开发约束**：先做一套完整可评审的交互 UI，再在独立技术验证阶段决定原生开发框架。未经明确批准不要从 M0 UI 阶段跨入真实文件与脚本执行。
