# M2.3 系统集成通信扩展

沿用既有 `{ id, version: 1, type, payload }` 请求及关联响应。仅 Workspace 接受 `system.*`；Mini/Dock 返回 `WRONG_SURFACE`。未知字段、重复字段、错误类型被拒绝，正常退出开始后不再接受新操作。

| 请求 | payload | 结果 |
| --- | --- | --- |
| `system.getState` | `{}` | 既有宿主 state，增加 `systemIntegration` |
| `system.setDesktopIcons` | `{ visible: boolean, firstHidePolicy?: "restore" \| "keepHidden" }` | `{ state, operation }` |
| `system.setIconExitPolicy` | `{ policy: "restore" \| "keepHidden" }` | `{ state, operation }` |
| `system.setStartup` | `{ enabled: boolean }` | `{ state, operation }` |
| `system.setHotkeys` | `{ dock: string, workspace: string }` | `{ state, operation }` |

桌面图标请求设置目标可见状态；首次隐藏必须明确提供策略，显示操作不接受首次隐藏策略。`operation.success` 是系统操作是否成功；桥接 `ok: true` 只表示请求已分派。前端不得将两者混淆。

`systemIntegration.desktopIcons` 包含 `success/code/message/visible/supported/firstHideAuthorized/exitPolicy/conflict/needsRecovery/recoveryPath`。`visible: null` 表示未知。恢复路径始终可见。外部修改冲突暂停自动恢复，明确的新目标操作才开始新一轮授权状态记录。

`systemIntegration.startup` 包含 `success/code/message/enabled/registeredCommand/expectedCommand/owned/needsRepair`。`registry_unavailable` 与 `startup_entry_unsupported` 表示状态无法可靠查询，不显示为已关闭。可查询但操作失败时仍显示真实的 `enabled`。可执行路径、Run 项位置与值名由宿主生成，前端不能指定。

热键使用至少两个 Ctrl/Alt/Shift 修饰键与字母、数字或 F1–F24（F12 除外）。Win 组合不可用。两组必须独立；注册冲突保留原来的有效组合。配置持久化失败会尝试回滚注册并报告失败。

既有 `settings.save` 增加白名单字段 `miniEnabled/miniOpacity/foregroundBlocklist`。屏蔽名单最多 100 个不带路径的 `.exe` 文件名，宿主规范化大小写并去重。桌面图标元数据、退出策略、启动项与快捷键不能通过通用保存绕过专用操作。外观防抖保存不包含上述独立系统字段，避免旧快照覆盖新设置。

本扩展没有任意 PowerShell/CMD、文件路径执行、任意注册表写入或前端传入 Shell 命令能力。应用库与场景仍沿用稳定 ID 和既有原生启动服务。
