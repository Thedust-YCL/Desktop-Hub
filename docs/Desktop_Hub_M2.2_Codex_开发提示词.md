# Desktop Hub — M2.2 文件虚拟索引、自动监测与标签系统开发任务

你现在担任 Desktop Hub Windows 桌面客户端架构师与开发工程师。

项目预期已完成：M0 HTML UI 原型、M1 Windows 原生宿主、M1.5 多应用库与独立启动、M2.1 场景化组合启动。本轮实施 **M2.2：文件资源管理系统**。

**任务目标：** 用户能够在不移动、不复制、不重命名、不删除任何原始文件的前提下，将 Windows 桌面及用户指定目录中的资源建立本地虚拟索引，以标签建立跨目录关联，自动反映文件变化，并在 Workspace 中搜索、收藏、浏览、打开及修复失效引用。

1. 阅读项目根目录 `PRD.md`（当前需求基线为 v0.7.1），尤其是 FM-01～FM-14、SourceRoot / Resource / ResourceSource / Tag / ResourceTag / TagSuggestion 逻辑模型以及相关验收标准。
2. 检查项目代码和 `docs/` 下已有 M1、M1.5、M2.1 实施报告（如存在）；核实 M2.1 实际完成状态，未实现项应如实记录，不得假设已实现。
3. 检查 Git 状态，保留用户的未提交改动；如条件允许，为上一阶段建立清晰的可回退版本。
4. 优先复用现有 WPF/WebView2（或实际已采用的）前后端桥接、持久化、错误处理和 Quiet Desktop UI。**不重写 Mini、Dock、Workspace、不更换客户端技术框架、不破坏应用库与场景引擎。**

## A. 索引来源和首次导入

**A1 桌面目录发现**
- 通过 Windows 系统的已知文件夹机制获取当前用户真实桌面目录，不硬编码 `C:\\Users\\...\\Desktop`；兼容路径重定向。
- 默认仅针对当前用户桌面。公共桌面必须由用户主动勾选；自定义目录必须由用户主动选择和授权。
- 若检测到 OneDrive 等重定向路径，显示真实路径和可能的同步标识；索引功能不能主动下载云端占位文件。

**A2 扫描预览和确认**
- 首次显示待索引来源、路径、文件/文件夹数量、权限及目录深度等信息，用户确认后才写入正式索引并开启监测。
- 用户未确认时，允许为预览读取必要的目录元信息，但不得持久化正式索引、后台监控或扫描未授权目录。
- 默认只索引来源目录的直接子项；子文件夹作为单个资源。允许为单独的文件夹开启递归索引。
- 用户新增自定义目录时也要经过授权；所有已授权来源默认自动监测，递归深度服从各自配置。
- 允许取消扫描；大量文件扫描不得阻塞界面线程；展示进度和可解释的失败提示。

## B. 虚拟资源索引和本地数据模型

在现有本地存储架构上落地或等价实现：
- `SourceRoot`：目录、来源类型（个人桌面 / 公共桌面 / 自定义）、递归开关、授权时间、监测状态、可用状态、最近核对时间。
- `Resource`：稳定资源 ID、当前路径、最后已知路径、显示名称、资源类型、扩展名、创建/修改时间、文件身份线索（若可靠可用）、状态、收藏、首次索引及最近看到时间。
- `ResourceSource`：资源与多个来源间的关系，避免嵌套/重叠来源产生重复资源。
- `Tag`、`ResourceTag`、`TagSuggestion`：正式标签与待确认建议分离。

要求：
1. 同一个文件即使出现在多个虚拟集合中也只能保留一个实际文件，不创建内容副本。
2. 业务资源 ID 不直接采用绝对路径；能够可靠识别重命名时保留 ID、收藏和标签。
3. 索引来源重叠时必须去重并维护来源关系；移除某个索引来源不应误删其他来源仍在引用的资源。
4. 本地写入须具备一致性处理、失败回滚或等效保障；重启后恢复数据。
5. 不能为了方便索引而修改用户原始文件、创建隐藏标记文件、自动移动文件或更改 Windows 文件属性。

## C. 文件系统监测与状态维护

- 对已授权来源使用事件驱动的文件系统监测（可使用 Windows/.NET 对应机制），处理创建、删除、重命名和文件夹变化。
- 实现事件合并、重复事件去重、短暂占用/权限失败的合理重试。
- 监测事件可能丢失、顺序颠倒或溢出；必须提供必要的重新核对机制，包括启动恢复、监测异常后及用户主动刷新。
- 不做持续高频全盘轮询；不可监测无授权的磁盘和目录。

状态至少包括：
- `Active`：原路径可访问。
- `Missing`：文件已无法通过原引用找到，但索引、收藏、标签仍在。
- `PendingRepair`：用户已进入手动修复流程。
- `SourceUnavailable`：来源磁盘/目录暂不可用，此时不能把所有子项当成永久删除。

行为：
- 可可靠识别的同目录重命名：更新路径并保留资源身份。
- 文件移动：首版不要求自动跨目录追踪；原引用失效时提示用户手动修复。
- 文件删除：保留索引及标签，标记缺失。
- 修复：用户重新指定目标路径并验证后，更新同一个资源 ID，不建立无谓重复项。
- 集中清理：用户筛选、勾选、二次确认后，仅清理应用自身的失效索引与关联元数据；严禁删除实际文件。
- 注意符号链接、目录联接点、重解析点、嵌套目录和循环引用，递归扫描不得失控或越过授权边界；处理无访问权限、断开的移动磁盘及其他异常。

## D. 非递归文件夹的临时浏览

- 未开启递归索引的文件夹仍可在 Desktop Hub 内临时浏览其子文件与子目录，亦可通过 Windows 资源管理器打开。
- 临时浏览**不等于**长期索引，不在后台替未授权的深层内容建立长期记录。
- 用户可主动将临时浏览中的单项文件加入授权索引，或显式为该文件夹开启递归索引。
- 保护路径处理：不得通过拼接前端任意字符串访问或修改任意系统文件；所有前端请求在原生层校验。

## E. 标签与离线建议

**E1 正式标签**
- 支持标签新建、重命名、删除，以及主题、时期、自定义标签类型。
- 单个资源可绑定多个标签，同一个标签可用于多个资源；支持添加、移除和多标签组合筛选。
- 不将标签变成真实目录，不复制资源。

**E2 建议规则**
- 仅使用本地文件名、目录名、文件创建时间等元信息生成简单可解释的建议。
- 时期建议优先以文件创建时间推导（如“2026年10月”），允许用户编辑，不假设它代表项目真实创作时间。
- 不接入在线 AI，不解析文件正文或图片内容，不生成媒体缩略图。

**E3 接受流程**
- 资源卡片内展示建议标签及建议依据。
- 支持一键接受、拒绝、编辑及手动添加。
- 未接受的建议不得写入正式 `ResourceTag`。
- 已拒绝的建议应保留处理状态，避免每次打开页面反复弹出相同建议。

## F. Workspace UI 和用户操作

保持已经认可的 Quiet Desktop 视觉方案：
- 在 Workspace 连接真实“文件资源库”入口，保留常用应用启动台和场景中心的现有布局。
- 资源库提供 **列表视图、类型图标网格视图、标签视图**；三者共用同一数据来源。
- 文件名搜索、标签搜索、多标签筛选、收藏及收藏筛选。
- 支持双击或明确按钮打开文件、打开文件夹，以及“在资源管理器中显示”。
- 图片、PDF 等在本轮**只显示文件类型图标**，不读取内容生成缩略图。
- 提供索引来源管理（增加来源、当前用户桌面状态、公共桌面可选、递归开关、监测状态、移除来源）。
- 提供资源状态标识（正常 / 缺失 / 需修复 / 来源不可用）和失效资源集中修复、清理界面。
- 扫描、文件打开失败等提示必须是真实的系统结果；前端不得用模拟数据冒充真实成功。
- Mini 与 Dock 的已有应用/场景快捷启动保持不变；本轮无需把完整文件库强塞进 Mini 或 Dock。

## G. 安全与性能边界

- **绝对禁止**在本轮执行文件物理迁移、批量重命名、删除、覆盖或自动整理；应用的“删除索引”必须与真实删除文件严格区分。
- 不实现桌面图标隐藏/恢复（留到 M2.3），不实现 Windows Shell 替换。
- 不收集文件内容、云同步、遥测，不主动上传路径和标签。
- 不在后台连续读取图片、PDF 内容；使用按需、分页/虚拟化展示来控制大量资源时的内存占用。
- 文件监测、扫描、数据库操作不应冻结 UI；支持取消或超时的操作应及时释放资源。
- 退出和重启后能恢复索引、标签及来源配置；异常关闭不能破坏已有应用库与场景配置。
- 当前项目若已有有效数据存储方式，优先复用；确有必要新增数据库时，需提供明确迁移/兼容逻辑并避免破坏旧配置。

## H. 测试与验收（必须实际验证）

所有写入或变更测试优先使用**临时测试目录与无害测试文件**；不得在真实用户桌面上进行破坏性实验。至少验证：

1. 自动定位当前用户的实际桌面路径，但不未经确认导入正式索引。
2. 默认只索引直接子项，文件夹不自动递归；用户能够单独开启递归。
3. 公共桌面和自定义目录未经授权不被监测，授权后正确生效。
4. 允许为多个目录建立索引；重复/嵌套来源不会产生无意义重复资源。
5. 新建文件和重命名可以正确同步；可识别重命名保留 ID、标签、收藏。
6. 删除原文件后留下 `Missing` 索引而非直接抹掉数据。
7. 来源磁盘/目录不可访问时显示 `SourceUnavailable`，不批量误判永久删除。
8. 手动修复无效引用后原标签和收藏保持不变。
9. 集中清理缺失索引只删应用数据库记录，不改变临时测试文件本身。
10. 非递归文件夹能临时浏览内部内容，但不会自动长期索引。
11. 主题、时期、自定义标签支持一个资源多标签及组合筛选。
12. 标签建议在接受前不成为正式标签；拒绝后不会不断重复出现。
13. 列表、图标网格、标签三视图均加载真实索引数据；搜索、收藏与打开功能可用。
14. 监听大量短时文件事件或监测异常后，索引能通过重核对回到正确状态。
15. 重启后授权来源、标签、收藏、索引关系仍存在。
16. 大目录扫描和监测不阻塞主要 UI，显示真实进度和错误。
17. 无网络环境下核心索引和标签功能仍可使用。
18. M1.5 多应用独立启动、M2.1 场景调度、Mini/Dock/Workspace、主题与快捷键均无明显回归。

测试报告逐项标明：实际通过 / 自动化测试通过 / 需要人工验证 / 未实现或失败。不要将模拟界面通过视为 Windows 功能验收通过。
