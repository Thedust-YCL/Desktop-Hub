# Desktop Hub M2.3 实施报告

日期：2026-10-10。版本：0.2.3。依据：`PRD.md` v0.7.1、M2.3 开发提示词、M1/M1.5/M2.1/M2.2 实施报告及当前源代码。

## 1. 交付结论与范围

本轮实现 Windows 托盘常驻、单实例请求转发、当前用户启动项管理、桌面图标整体可见性控制、独立全局快捷键、前台保护、窗口优先级与恢复记录。既有 Quiet Desktop Mini/Dock/Workspace 布局、应用库、场景引擎、文件资源库继续复用。没有新增第二套业务模块，没有修改桌面文件或替换 Explorer，没有进入 V1 安装包、更新与正式分发阶段。

代码与自动化验收已完成；**真实图标变更、当前用户启动项写入、实际登录/注销和真实 Explorer 重启仍待可恢复测试用户环境人工验收**。本机只查询真实 Shell/HKCU 状态；系统写入、异常恢复使用 Mock 测试。不能把 Mock 通过视为所有 Windows 系统组合已通过。

## 3. 实际实现与关键模块

### 桌面图标

`DesktopIconVisibilityController` 管理授权和恢复策略；`DesktopIconVisibilityService` 使用 Windows Shell 后端。通过公开的 `IShellWindows.FindWindowSW(SWC_DESKTOP)`、`IServiceProvider`、`IShellBrowser.QueryActiveShellView` 获取桌面 `IFolderView2`，读取 `GetCurrentFolderFlags`，仅以 `FWF_NOICONS=0x1000` 掩码设置目标状态。每次重新取得并释放 COM 对象，避免保留 Explorer 重启后失效的引用。没有硬编码 WorkerW 窗口链、盲目 Toggle、桌面文件迁移或 Explorer 重启操作。[微软桌面视图获取示例](https://devblogs.microsoft.com/oldnewthing/20130318-00/?p=4933)、[FOLDERFLAGS](https://learn.microsoft.com/en-us/windows/win32/api/shobjidl_core/ne-shobjidl_core-folderflags)。

首次隐藏说明不删除文件，两个策略均无默认选择；取消不写系统或授权。先保存已知初始状态、策略与待执行意图，再调用 Shell，再读取实际结果，最后保存完成记录。重复请求同一状态不反转。恢复失败保持恢复责任；能确认系统未改变的失败允许安全重试；无法核对则保留待恢复证据。配置无法保存时不开始系统变更。系统已改变但完成记录未保存时明确返回失败与实际状态，保留先前意图。

正常完整退出仅在授权、恢复策略、初始/当前状态明确且未检测外部冲突时恢复。初始隐藏时不会擅自变为显示。已观察到的外部修改会锁存冲突，包括退出时首次观察到的变化；之后不会无声覆盖。启动只核对和提示，不自动隐藏/恢复。注销/关机与完整退出分开，保留恢复记录，避免在 Shell 关闭过程中写入。

**兼容性限制：** 本机 Windows 11 对公开接口的真实读取成功，但写入尚未在安全用户环境验证。微软 `SetCurrentFolderFlags` 文档对 Windows 7 及以后提示与 `FVO_CUSTOMPOSITION` 配合；当前实现为了不改动图标布局，仅修改 NOICONS，未另行调整视图定位选项。不同 Shell 版本是否应用该目标需要实际验收；失败或核对不符会明确反馈，不回退到脆弱窗口链。[SetCurrentFolderFlags 文档](https://learn.microsoft.com/en-us/windows/win32/api/shobjidl_core/nf-shobjidl_core-ifolderview2-setcurrentfolderflags)。

### 托盘、单实例与生命周期

`TrayLifecycleService` 创建单一 NotifyIcon，菜单具备打开 Workspace、显示/隐藏 Mini、设置、显示/恢复图标和完整退出。隐形顶层 HWND 接收 `TaskbarCreated`，对同一个图标重建；原生测试仅向本实例窗口发送该消息，没有真正重启 Explorer。

`SingleInstanceService` 使用当前 SID、会话和稳定 profile 标识形成命名互斥标记；第二进程经 `CurrentUserOnly` 命名管道发送固定 `WORKSPACE\n` 命令并退出。不接受任意命令、附加字节或前端 PID。Windows 前台授权只面向已连接管道的服务端 PID，焦点获取仍可能被系统拒绝。[PipeOptions 文档](https://learn.microsoft.com/dotnet/api/system.io.pipes.pipeoptions)。

关闭 Workspace 仅保存/隐藏窗口，保持托盘、监听和文件监测。完整退出先停止新唤出与定时调度、取消待执行场景调度、保存窗口、按策略核对图标，再注销热键、释放托盘，最终释放窗口/WebView、监听与资源服务。取消调度不终止已经启动的独立用户应用。

### 当前用户开机自启

`StartupRegistrationController/Service` 使用当前用户 `HKCU\Software\Microsoft\Windows\CurrentVersion\Run` 的 `DesktopHub` REG_SZ 值。命令固定为 `"完整 EXE 路径" --startup`，处理空格与参数，超过官方 260 字符限制拒绝并提示移动至较短路径。查询不创建注册表键。首次运行默认关闭，不写 HKLM/RunOnce、计划任务或管理员项。[微软 Run 机制](https://learn.microsoft.com/en-us/windows/win32/setupapi/run-and-runonce-registry-keys)。

仅精确匹配本地成功/待确认命令记录的项目可更新或删除；同名外部项不覆盖。先持久化同意和待确认命令，再写单个值，再查询。失败保留真实系统状态和归属证据；禁用失败后重启仍可安全重试。便携目录移动显示不一致提示，用户明确开启时才修复旧的自有路径。普通启动与 `--startup` 均安静常驻，不弹 Workspace、不执行场景、不自动隐藏图标。

`enabled` 表示本程序当前路径的 HKCU Run 命令匹配；不代表已经核实任务管理器 StartupApproved、组策略或实际登录执行。注册表没有公开原子比较交换，写入前双重核对只能缩小并发外部改动窗口。同命令的外部写回也无法与原条目区分。

### 窗口、热键、前台与外观

`HubApplication` 继续协调既有三窗口，优先级 Workspace → Dock → Mini。Mini 不永久置顶，Dock 仅展开时覆盖普通窗口；异步创建使用代次防止旧请求在关闭/退出后重新弹出。修复 Dock 初始化期间的二次唤出与隐藏窗口的原生回复竞争；请求回复完成前不挂起 WebView。

`GlobalHotkeyService` 使用 RegisterHotKey/MOD_NOREPEAT，两组默认 `Ctrl+Alt+D`、`Ctrl+Alt+W`。先注册新组合再释放旧组合，冲突保留旧的两个有效绑定。组合限定至少两个 Ctrl/Alt/Shift 加字母、数字或 F1–F24（F12 除外），不占用 Win 系统组合。更改、销毁与退出时注销。[RegisterHotKey 文档](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-registerhotkey)。

`ForegroundProtectionService` 根据前台 HWND、进程名和监视器覆盖几何保护全屏/屏蔽程序，自己的窗口与桌面排除。名单按完整 `.exe` 文件名匹配，不注入、不终止程序。保护阻止系统快捷键/托盘/IPC 唤出和边缘悬停，并隐藏 Mini；前台保护解除后 Mini 恢复。普通程序约 500ms 悬停继续复用已有实现。几何判断可能把全屏浏览器/视频视为保护，也可能漏判特殊游戏，名单提供明确覆盖；不宣称 100% 游戏识别。

WPF PerMonitorV2、逻辑单位与工作区夹取保持；DPI/分辨率消息后重新夹取，超大/离屏窗口有真实测试。当前实机为单显示器 200% DPI；其他缩放和多显示器矩阵未通过实测。Esc 沿用先关对话框再关面板，并核对原窗口句柄及 PID；无效目标安全回退，Windows 拒绝前台激活时记录真实结果。

系统主题读取缓存，UserPreferenceChanged 更新，取消每 100ms 读主题注册表。悬停开启时 100ms 轻量原生查询，关闭时 1000ms；隐藏 WebView 挂起，支持关闭透明效果/动画。没有截图轮询或忙等待。M2.2 授权目录服务仍单实例后台监测。

### 设置界面与通信边界

沿用 Quiet Desktop 设置导航、卡片和控件，只补系统集成项及 Mini 透明度。前端显示真实状态、失败、冲突与重试；启动项不可读取不误显示关闭。设置字段沿用原子存储；防抖外观保存不携带独立系统字段，避免旧快照覆盖新设置。

`SystemBridge` 仅 Workspace 接受五类显式系统请求，类型、字段与重复键严格验证。通用 settings.save 不能写图标元数据、启动项或快捷键；没有任意 CMD/PowerShell、注册表位置或可执行路径接口。详情见 [M2.3 通信扩展](M2.3_Bridge_Protocol.md)。

## 7. 系统恢复方式与残余限制

### 软件未运行时恢复桌面图标

1. 在桌面空白处右键。
2. 打开“查看”。
3. 勾选“显示桌面图标”。菜单文字随 Windows 语言变化。

这条恢复路径不依赖 Desktop Hub，不删除或移动文件。软件可运行时也可使用“设置 → 系统与恢复 → 显示桌面图标”或托盘对应项。出现未知/失败时先使用 Windows 原生路径，不删除恢复记录来猜测状态；再次启动只核对，不无声执行。

已观察外部变更会暂停自动恢复；没有被观察到的外部显示→隐藏往返无法检测。磁盘/权限失败时当前进程仍锁存冲突，但跨崩溃持久化不能保证。Shell最后核对与写入间存在极窄的外部并发改动窗口。关机/注销时不承诺即时自动恢复；保留日志并在下次启动提示。无法保证所有系统中自动恢复成功。

### 禁用或修复开机自启

优先在设置中关闭，宿主只删除匹配本地归属记录的 `DesktopHub` 值；真实删除失败会显示仍启用/不一致，可重试。便携路径移动后明确开启可更新自有旧路径。启动项不属于本程序记录时，不自行覆盖。

软件无法启动时可在 Windows“任务管理器 → 启动应用”核对/禁用对应项；或用注册表编辑器检查当前用户 `HKEY_CURRENT_USER\Software\Microsoft\Windows\CurrentVersion\Run` 下 **DesktopHub** 值，确认完整 EXE 命令确实属于此软件后，仅删除该值，保留整个 Run 键和其他程序项。必要时先导出该键作备份。实际登录生效还受任务管理器与系统策略影响，当前程序只声明注册状态。

### 配置恢复

继续使用现有原子替换与损坏隔离逻辑。备份/恢复 `settings.json` 时完整退出，保留 `resources.json` 和恢复记录；schema4旧版本兼容性不能反向保证，代码回退前先备份配置。损坏记录被保留而不是默默销毁用户应用库。
