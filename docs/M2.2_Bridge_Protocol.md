# M2.2 资源库通信与持久化

继续使用 version=1 的 WebView2 请求/应答封包、允许的本地 origin、CSP 和参数白名单。资源接口只在 Workspace 接受。前端没有自由路径扫描、自由 Shell 命令、文件修改或文件删除接口。

| 请求 | 参数与结果 |
| --- | --- |
| resources.discover | 无参数；返回 Windows 已知文件夹机制登记的个人桌面真实路径和可能的同步标识，不扫描、不索引 |
| resources.preview | operationId、recursive；kind=desktop/publicDesktop/custom，或已有 sourceId，或 native browseToken。公共桌面首次预览要求 authorizePublic=true，界面由用户勾选；自定义路径只由原生目录选择器产生。返回 15 分钟有效的 token、路径、数量、深度策略、警告 |
| resources.cancel | operationId；取消活动扫描并废弃预览 |
| resources.confirm | token；原子登记来源和预览元信息，再核对与启动监测。重复同路径来源更新既有记录，不重复登记 |
| resources.query | query、tagIds、favoritesOnly、invalidOnly、status、page；文件名或正式标签检索，多标签为 AND，每页 60 项。只传所需页及来源、标签元信息 |
| resources.refresh | operationId；重新核对已授权来源，异步进度事件 |
| resources.removeSource | sourceId、confirmed；停止对应监测并移除孤立索引，其他来源关系保留 |
| resources.favorite | resourceId、favorite |
| resources.beginRepair / resources.repair | resourceId；进入 PendingRepair，再由原生选择器选择同类型目标，沿用原 ID/标签/收藏。已有目标索引合并至原 ID，外部目标只授权该单项 |
| resources.clean | resourceIds、confirmed；只清理 Missing/PendingRepair 元数据，SourceUnavailable 不可批量清理 |
| resources.saveTag / resources.deleteTag | tagId（新建可省略）、name、kind；删除额外要求 confirmed |
| resources.bindTag | resourceId、tagId、bind；正式多对多关系 |
| resources.suggestion | suggestionId、accept、editedName（可选）；建议必须显式接受，拒绝状态持久化 |
| resources.browse | resourceId，或 token+name；page；仅返回授权文件夹的临时子项与原生 token，不持久化。拒绝路径片段、链接、越界和失效会话 |
| resources.addBrowsed | token、name；只登记由当前浏览会话选中的单项 |
| resources.open | resourceId，或 token+name；mode=open/folder/reveal；原生重新验证存在性、链接/云占位/文件身份后提交 Windows 请求。成功仅表示提交，不代表关联软件完全加载 |

事件：`resources.changed` 通知重新查询；`resources.progress` 包含 operationId/count/path/phase。Mini/Dock 不加载资源页，也不广播完整资源表。

所有变更由原生服务串行化。`resources.json` schemaVersion=1 使用与既有 SettingsStore 相同的临时文件、Flush(true)、原子替换原则，事务失败保留原文件和内存状态。应用与场景的 settings.json schemaVersion=3 不变，无数据迁移。损坏的资源文件保留原样，资源写入停止，错误在资源页展示；不影响应用与场景配置。

SourceRoot 与 Resource 通过 ResourceSource 多对多关联，按规范化路径去重。Resource ID 是独立 GUID；可可靠匹配的同目录重命名使用卷号/文件 ID 或系统重命名事件保留身份，目录重命名的子项以身份核对后更新。跨目录移动留待人工修复。ResourceTag 是正式关系，TagSuggestion 的 Pending/Accepted/Rejected 状态独立保存。

监测为 FileSystemWatcher 事件驱动；约 400ms 合并、事件持续时约 2 秒触发核对。运行中的新事件保留再次核对请求，重命名提示队列最多 2048 条，溢出由完整核对兜底。启动、监测错误和手动刷新均重新核对；60 秒低频检查只用于来源健康/不可用恢复，不做全盘轮询。单项授权用精确文件过滤的监测器，不扫描外部目录兄弟项目。

扫描仅访问元信息；单次上限 100000 项，递归深度上限 64 层，超限给出提示。普通符号链接、联接点与未知重解析点不继续遍历；识别的 Cloud Files 重解析标签与链接区分，已可本地读取的目录可扫描。云占位目录不展开，云占位文件不通过资源库启动下载。文件身份句柄只使用 FILE_READ_ATTRIBUTES、共享读写删除、OPEN_REPARSE_POINT、OPEN_NO_RECALL，不读取文件内容。资源库只显示类型图标。脚本、可执行文件、快捷方式等执行性资源需在应用库/场景中配置，或在资源管理器中处理，资源库不直接执行。
